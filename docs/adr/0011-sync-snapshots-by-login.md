# 憑證快照以「同一次登入」同步；切換時一併寫回帳號資訊

取代 ADR-0002。

ADR-0002 假設刷新只換 accessToken、refreshToken 不變。實測推翻了這一點：Claude Code 每次刷新都會輪替 refreshToken，舊的立即作廢。所以憑證快照只要它的帳號當過當前憑證帳號、被刷新過一次，就會變成廢檔。另外兩個實測結果也影響設計：執行中的 Claude Code session 會改用檔案裡的新憑證，不需要重新啟動；Claude Code 把用量歸給哪個帳號，看的是 `~/.claude.json` 的 `oauthAccount`（帳號資訊），不是憑證本身。

決定如下：

- **納管時**：從帳號資訊取得帳號識別碼並綁定（沿用 ADR-0002）；同時把整份帳號資訊和憑證快照存在一起。
- **憑證同步**：當前憑證的 refreshToken 到期時間跟某份憑證快照相差 60 秒以內、而且只有這一份符合，就判定兩者出自同一次登入，把當前憑證寫回那份快照；有兩份以上符合時不寫。到期時間由供應商依登入固定，同一次登入裡的輪替不會改變它，重新登入則會。Claude Code 存的是「本機時間加剩餘秒數」，每次刷新會有一兩秒的抖動，所以不能要求完全相同。這個規則比的是到期時間，不看事件先後，所以本工具沒在執行的期間發生的刷新，下次啟動時一樣補得上。
- **切換時**：寫入目標的憑證快照，並且只改寫 `~/.claude.json` 裡的 `oauthAccount` 這一個鍵（讀出、修改、整份寫回），其他內容一律不動。切走之前先同步一次；同步失敗就拒絕切換。
- **只有帳號資訊、沒有同一次登入的證據時，不寫入**：例如對同一個帳號重新登入。這種情況標為失效的憑證快照，由使用者重新納管。

## 失效旗標分兩段；觀測記下到期時間

失效旗標要保留到重新納管，但 `/login` 先寫憑證、後寫 `oauthAccount`：空窗那一輪，新登入的憑證看起來像原帳號「重新登入」，原帳號會被誤標。所以旗標分兩段存在上一輪的觀測裡：當前憑證帳號的那一份是暫定的，同一份憑證下帳號資訊改變時跟著改判；切換離開時才轉為持久，之後只有重新納管（憑證指紋換掉）才熄滅。代價是「重新登入後一直沒切走」的旗標要靠暫定那一段撐著，兩段都得向下相容舊檔。

上一輪的觀測也記下當時當前憑證的到期時間。命令列不同步、寫回失敗時，快照還是舊的憑證指紋，光看指紋會把同一次登入的輪替誤判成切換；到期時間跟上一輪同一次登入，就不算切換。這和憑證同步共用同一條「60 秒內」的判定，所以也承擔同樣的風險：兩個帳號在同一分鐘內登入，會被當成同一次登入。

## Considered Options

- **用額度快取裡的帳號識別碼證明當前憑證屬於誰**：否決。實測發現這個識別碼是從 `oauthAccount` 抄來的，不是查詢回應給的；憑證和 `oauthAccount` 不一致時，它也跟著錯。
- **帳號識別碼對得上、連續幾輪穩定，就自動重新納管**：否決。帳號識別碼只是旁證：`/login` 會分兩次寫入憑證和 `oauthAccount`，中間有空窗；有些切換工具只複製憑證檔，`oauthAccount` 會長時間停在舊帳號。只要誤判一次，就會用別的帳號的憑證蓋掉快照。代價是每次重新登入同一個帳號之後，都要手動重新納管一次。
- **到期時間之外，再要求帳號識別碼一致才寫回**：否決。別的工具只換憑證、沒換 `oauthAccount` 時，到期時間能指出正確的快照，識別碼卻是錯的，這條規則反而會擋掉正確的寫回。
- **只在本工具切走時寫回**：否決。使用者自己用 `/login` 換帳號時，被換走的那個帳號已經輪替過的憑證就接不到了。
- **切換時只換憑證，不換帳號資訊**：否決。實測會造成錯配：執行中的 session 用新帳號的額度，畫面上和額度快取卻記在舊帳號名下。

## Consequences

- 舊版納管的憑證快照沒有帳號資訊，升級後是僅監看帳號，重新納管一次才能切換。直接放進納管目錄的憑證檔也一樣。
- 本工具會在背景寫入憑證快照。寫入沿用 ADR-0007 的權限收緊；寫回失敗會重試，期間該帳號不能切換。
- 「同一次登入裡，到期時間在輪替前後只差一兩秒」已經在三條輪替鏈上觀察過：兩條強迫刷新、一條自然刷新，觀察到的最大差距約 1.2 秒。refreshToken 到期之後，Claude Code 是否真的要求重新登入，目前還不知道。
- 憑證指紋每次刷新都會變，所以它只用來判斷「當前憑證和某份快照是否相同」，不再用來判斷是否發生了切換。判斷切換時，指紋改變、`oauthAccount` 仍是同一個帳號，就不算切換（ADR-0009）。
