# 憑證快照不加密，只主動收緊權限

憑證快照以明文存放在 `~/.claude-multi/`。`cli add` 建立目錄和檔案時，會主動收緊權限，不依靠繼承：Windows 移除繼承，只授權目前的使用者；POSIX 目錄設 700、檔案設 600。事後檢查權限，不符合就修正並發出告警。不加密的原因是：金鑰只要跟資料存在同一台機器上，能讀到快照的攻擊者一樣讀得到金鑰，加密沒有實質提升。

## Considered Options

- **自訂金鑰加密**：理由同上，只是增加複雜度。
- **Windows DPAPI（綁定目前使用者帳號）**：這是真正有效的做法，而且用標準庫的 `ctypes` 就能呼叫。但它會讓「直接把憑證檔放進納管目錄」這條路失效，快照也無法帶到別台機器使用。留待切換功能時，交給架設者選擇。

## Consequences

風險集中度確實提高了：Claude Code 自己只存一個帳號的憑證，本工具則集中存放 N 個長效 refreshToken，一次外洩就是全部帳號。不過其他非管理員使用者本來就讀不到使用者目錄，收緊權限之後，防護程度至少不低於 Claude Code 自己的做法。

切換功能上線時再評估過一次，維持不加密：切換沒有讓憑證快照的存放位置或數量改變，暴露面與先前相同。
