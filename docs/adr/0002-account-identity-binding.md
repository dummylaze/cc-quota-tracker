# 納管時綁定帳號識別碼，以 refreshToken 雜湊偵測切換

`~/.claude/.credentials.json` 裡沒有任何穩定的帳號身分欄位，額度快取裡的帳號識別碼又要等 Claude Code 下一次讀取額度才會跟著變，可能落後好幾個小時。因此分成兩個訊號：納管帳號的當下（使用者剛執行 `claude login`）就從 `~/.claude.json` 取得帳號識別碼，和那份憑證快照綁定；平常則每輪比對當前憑證 refreshToken 的雜湊，幾秒內就能偵測到切換並知道切到哪個帳號。實測刷新只會更換 accessToken，refreshToken 不變，所以雜湊不會把刷新誤判成切換。

## Considered Options

- **只靠額度快取裡的帳號識別碼**：太慢，切換後這段時間的用量會算到錯的帳號上。
- **對整份憑證檔做雜湊**：每次刷新都會被當成一次切換。
- **只用 refreshToken 雜湊，識別碼之後再學**：首次安裝時所有帳號都會落在「無法確定」的狀態，直到每個帳號各發過一次 prompt。

## Consequences

直接把憑證檔放進納管目錄、沒有經過納管指令的帳號，沒有綁定，要等額度快取出現它的識別碼才能補上。refreshToken 是否會在接近到期時輪替尚未觀察到。若會輪替，雜湊改變但帳號識別碼不變，可以跟切換區分開來：工具只會提示「該帳號的憑證快照已失效，請重新納管」，不會自動改寫憑證快照，因為一旦誤判就會用別的帳號的憑證蓋掉它。
