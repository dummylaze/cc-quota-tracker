# 查詢額度：請 Claude Code 代查，手動為主，落後時可選擇自動

只讀額度快取有一個 ADR-0001 當時沒寫下的代價：持續對話時，額度快取只在 `/usage`、登入等時機才更新，工具的讀數會系統性落後，一小時以上很常見。VS Code 擴充套件的面板雖然每輪都顯示最新數字，但那份數字來自 Claude Code 子行程隨模型回應送出的事件，只存在擴充套件的記憶體裡，不寫進任何本機檔案，外部讀不到。

因此本工具可以「查詢額度」：開一個 `claude` 子行程，以 stream-json 控制請求送出 `get_usage`，由 Claude Code 用自己的憑證向供應商查詢，並寫回額度快取。面板的 Account & usage 對話框（也就是面板裡的 `/usage`）送的就是同一個請求。工具不碰 token、不發自己的網路請求，也不拿查詢的回應當資料來源（只用它判斷查詢何時結束、取得錯誤訊息）；額度快取仍然是用量讀數的唯一來源，查詢成功與否也只看它的觀測時間有沒有前進。子行程一律關閉 hooks，避免觸發使用者自己的 hooks。

觸發方式只有兩種：使用者按下按鈕或下命令列指令；或使用者開啟「自動查詢」後，在讀數落後或讀數待更新時自動查詢。自動查詢預設關閉，間隔有下限，連續失敗會暫停，避免工具變成定時輪詢供應商的端點。

## Considered Options

- **statusLine 當第二資料源**：VS Code 面板模式不會執行 `statusLine`，只有在終端機使用 Claude Code 時才有資料；而且不帶帳號識別碼、只有兩個窗口，還要額外處理歸屬、合併、多 session 寫入。
- **模擬鍵盤在面板輸入 `/usage`**：要搶焦點、找視窗，面板一改版就壞。
- **固定間隔定時查詢**：等於讓工具定時打供應商的額度端點，正是 ADR-0001 否決的「定時呼叫 `/api/oauth/usage`」，只是改由 Claude Code 代打，429 風險相同；限流期間連使用者自己的 `/usage` 也會失效。
- **解析 `get_usage` 的回應**：能少等一次快取寫入，但會多一條資料路徑，而且直接依賴一個官方標為實驗性的介面格式。

## Consequences

- `get_usage` 在 Claude Code 裡被標為實驗性、可能變動。它壞掉時，查詢會失敗並提示「可改在 Claude Code 執行 `/usage`」，讀數照常沿用額度快取。
- 只能查使用中帳號；待命帳號仍只顯示最後一次觀測到的讀數。
- 「不修改 Claude Code 設定、不掛 statusLine 或 hooks」（ADR-0006）不變。
