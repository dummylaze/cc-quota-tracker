# 以 PyInstaller 資料夾模式發佈不簽章的 zip，分成視窗與命令列兩個 exe

沒有 Python 的人也要能用，所以另外提供打包好的 Windows 版本。PyInstaller 只在建置時用到，執行期仍然不依賴任何 pip 套件（ADR-0004）。決定如下：

- **資料夾模式，以 zip 發佈**：解壓縮後只有一個行程，記憶體沿用 ADR-0004 的上限來驗收。
- **兩個 exe 放在同一個資料夾**：`cc-quota-tracker.exe` 是視窗程式，雙擊開啟、不開主控台，開機自動啟動也登錄它；`cc-quota-tracker-cli.exe` 是主控台程式，給 `add`、`remove`、`list`、`query`、`check` 用。Windows 的 exe 在建置時就決定它是主控台程式還是視窗程式，一個 exe 沒辦法兩者都是。
- **不簽章**：第一次開啟會出現 SmartScreen 警告。Release 附上 SHA-256，建置在 GitHub Actions 上進行並留下公開紀錄，讓人能確認 exe 確實出自公開的原始碼。
- **不做安裝程式、不做自動檢查更新**：升級就是覆蓋解壓縮。檢查更新要連網，本工具不新增網路呼叫（ADR-0001、ADR-0010）。

## Considered Options

- **單一檔案模式**：否決。每次啟動都要先解壓縮到暫存目錄，會多一個 bootloader 母行程，記憶體要算兩個行程，啟動也比較慢。
- **只做一個主控台 exe**：否決。雙擊或開機自動啟動時，主控台會閃一下。
- **只做一個視窗 exe，再把輸出轉回終端機**：否決。輸出重導向和結束代碼都不可靠，腳本沒辦法依賴它們。
- **Nuitka**：否決。建置時要另外裝 C 編譯器，建置也比較慢。
- **Python 官方的嵌入式發行版**：否決。它不含 tkinter，要自己補 Tcl/Tk。
- **付費簽章**：否決。每年都要付費，相對於這個工具的規模不划算。

## Consequences

- 兩個 exe 的檔名和資料夾結構，一發佈就會有人依賴：開機自動啟動的登錄值、使用者自己寫的腳本都會指向它們，之後改名要另外處理遷移。
- 沒簽章的 exe 可能被防毒軟體誤判。README 要說明怎麼比對 SHA-256，以及改用原始碼部署的退路。
- 原始碼部署繼續支援。開機自動啟動只有一個登錄值，誰打開開關就寫入誰自己的啟動命令；另一種部署看到的會是「關閉」。
