# 06: 報表分頁「總覽」

**What to build:** 報表換成正式的分頁畫面，第一個分頁是總覽：使用者一眼看到區間內的總 token、cache 命中比例、估算金額，每日長條圖依帳號分色堆疊，下方是各模型的表。分頁框架與共用控制（區間、單看或合計）也在這張建好，07、08 接著加分頁。版面參考原型（本機分支 `prototype/token-report` 的 `?variant=A`），以 spec 為準。

**Blocked by:** 02, 04

**Status:** resolved

## Acceptance criteria

- [x] 實作前與使用者確認：分頁名稱的字樣、帳號的配色、數字在哪個量級換單位
- [x] 分頁框架：頁首放產生時間、示警橫幅、區間選擇（近 7 天、近 30 天、全部）、單看某個帳號或全部帳號合計；切換分頁時保留選擇
- [x] 三個總數：總 token（附 cache 讀取與寫入）、cache 命中比例（附算法）、估算金額（含未知部分時標示）
- [x] 每日長條圖：合計時依帳號分色堆疊，未歸屬也是一段；單看一個帳號時不堆疊，只用該帳號的顏色；每段有完整數值的提示
- [x] 各模型的表：合計 token、cache 寫入、cache 讀取、命中比例、金額；input、output 等其他欄位可以展開
- [x] 顏色只代表帳號，不拿來表示模型或其他意義
- [x] 數字格式：正體中文用萬、億，英文用 K、M、B；完整數值放在滑鼠停留提示裡
- [x] 淺色、深色兩種主題都正確，跟著系統設定
- [x] 審美驗證（對比度、留白、高彩度面積等量測，兩種主題）達標
- [x] 計算邏輯的既有測試不受版面影響，全部通過

## Comments

- 2026-10-22：**實作完成**。
- 使用者定案（實作前確認）：分頁名稱「總覽／每日／帳號」（英文 Overview / Daily / Accounts；本票只有總覽，另兩個分頁在 07、08 加）；帳號配色沿用原型的 4 色（淺色藍 #2f63c9、青綠 #17795f、琥珀 #9a5b0c、紫 #7a4fb0，深色版只調明度），第 5 個帳號起從頭循環，未歸屬固定用中性灰；大數字 1 萬／1 億（K／M／B）起換單位、三位有效數字，完整數值放滑鼠停留提示。已知取捨：第 5 個帳號與第 1 個同色，只能靠圖例與提示的名稱分辨。
- 票面外、實作時自補的決定（審查時逐條請審查者判斷，皆認為合理）：
  - 報表資料的 `summary` 多帶 `days`（日軸）、`daily`（日 × 帳號的 token 數）、各模型細分（`accounts[].models`、`total.models`）與 `tokens`、`cacheWrite` 兩欄，`accounts[]` 多帶 `color`（角色名）：畫面的算術只剩加總與排版，邊界留在 Python 端才測得到。用量比今天還晚（時鐘被調過）時日軸延到那一天，免得該日的長條被丟掉。
  - 帳號顏色是 `tokens.THEMES` 的新角色（`account_1`～`account_4`、`unattributed`），對比度與「互不相同、不借用當前憑證／嚴重度／中性色」都有測試。
  - 頁面只有一個分頁，仍畫分頁列與登錄表（`TABS`），讓 07、08 直接加；「切換分頁時保留選擇」的做法是選擇存在分頁之外的 `state`，目前只有一個分頁，還沒有實際切換可驗。
  - 「單看」只列區間內有用量的帳號；選到的帳號在別的區間沒有用量時顯示「這個區間沒有用量」。未歸屬不能單看（單看時不列）。
  - 長條圖是行內 SVG（座標刻度取 1、2、5 乘 10 的次方，去尾端 0），每段有 `<title>` 提示；SVG 命名空間借用 HTML 解析器造出的 `<svg>`，頁面裡不出現任何網址（既有測試禁止）。每次點擊整頁重建，重建後把鍵盤焦點還給同一個按鈕。
  - 各模型表預設欄位：合計 token、cache 寫入、cache 讀取、命中比例、金額；展開再多 input、output、cache 寫入（5 分鐘、1 小時）。
  - 金額磚沿用票 04 的整數美元規則，所以不到 1 美元時會顯示 $0 或 $1（提示仍到分）。
  - 大數字換算 `makeCompact` 寫在頁面腳本，`tests/test_report_numbers.py` 抽出它交給 Node 跑（沒有 Node 就略過）。
- 畫面驗證（無頭 Edge 截圖加算式量，淺色／深色、中文／英文、單看帳號、展開欄位、空狀態都截過）：對比度沿用 `test_tokens` 逐對量（新增報表用的 fg／sub 在底板上、反白按鈕、帳號色在卡片上，皆過 WCAG AA 與 APCA 目標）；留白率（像素膨脹的近似量法）73.7～84.5%；高彩度（chroma > 0.1）面積 0.5～8.8%（5 個帳號堆疊、近 30 天最高）；邊框一律 1px（焦點外框 2px 是 outline），無漸層、無 Emoji、無左側彩色邊條；字型只有一個家族，字級 6 階、字重 2 種，皆具名。
- 審查（兩軸＋變異）：Standards 無硬違規；採納：`tile` 的參數 `big` 遮住同名函式而改名、`token_report.py` 兩處塞在引數裡的運算式拆成具名變數。Spec 軸驗收十條逐條屬實；採納：每次重建丟掉鍵盤焦點（補還原焦點與 `aria-controls`）、極小的段高度不足 1px（補下限）、日軸延長的邊界沒有測試（補測試並重跑該變異確認轉紅）、`daily` 裡等價的守衛刪除。變異 16 個，14 個一開始轉紅，2 個全綠已處理。未採納：zh 的「總 token」與表格欄頭「合計 token」用詞不同（前者是票面的字樣、後者是 spec 的字樣）；字級階層放在頁面而不是 `tokens.py`（那裡是視窗用的 pt 字級）。
- 2026-10-22：**結案後的決定（使用者）**：金額磚（頭條數字）在已知金額不到 100 美元時顯示到分，免得剛開始用時看起來像沒花費（$0）；表格裡的金額格維持整數美元、提示到分（票 04 的規則不變）。第 5 個帳號與第 1 個同色的取捨維持原樣，用到 5 個以上帳號時再調整配色。
