# 05: 帳號標籤對照

**What to build:** 憑證快照移除後，綁定跟著清掉，歷史用量會查不到帳號標籤。報表另外保存一份「帳號識別碼 → 最後用過的帳號標籤」，讓已移除的帳號仍以原標籤顯示；從沒納管過的帳號依首次出現的順序編成「未監看帳號 n」，編號固定。

**Blocked by:** 02

**Status:** resolved

## Acceptance criteria

- [x] 每次產生報表時依現有的綁定更新對照；憑證快照移除後，該帳號的歷史用量仍顯示最後用過的帳號標籤
- [x] 改了帳號標籤後，該帳號的歷史用量改用新標籤，不拆成兩個帳號
- [x] 從沒有綁定過的帳號識別碼，依首次出現的順序顯示為「未監看帳號 n」；之後再產生報表，編號不變
- [x] 對照含帳號識別碼，放在納管目錄的工具狀態裡，收緊權限的方式比照切換紀錄；報表 HTML 裡只出現帳號標籤
- [x] 測試走命令列 `report --no-open`、跑在假 home 上，涵蓋移除、改名、未監看帳號的編號穩定
- [x] 既有測試全部通過

## Comments

- 2026-10-22：**實作完成**。對照是 `.state/account-labels.json`（`labels`：帳號識別碼 → 最後用過的標籤、`unwatched`：帳號識別碼 → 編號），經 `ManagedDirectory` 讀寫、權限比照切換紀錄；只在產生報表時更新（`report --update-ledger` 不碰）。
- 票面外、實作時自補的決定（審查者逐條判斷過，皆認為合理）：
  - 對照讀不到（作業系統層的讀取錯誤）時不寫檔，編號只在該次報表有效；寫不成也照常產生報表。兩種情形都在報表頂端與 stderr 示警（新增示警種類 `labelsUnavailable`）。讀不懂的檔案視為空並覆寫；內容裡不合規格的項目（標籤非字串或空字串、編號非整數或小於 1）讀回時略過。
  - 對照記下所有現有綁定的帳號（含還沒有用量的），讓「報表產生過之後才移除」以外的情形也盡量有標籤可沿用。
  - 編號只增不重用：帳號後來被納管了仍保留原編號；沒有用量、只出現在切換紀錄裡的帳號也會佔掉一個編號（所以可能看到「未監看帳號 1、3」）。
  - 同一個帳號識別碼綁了多份憑證快照時，顯示標籤依字母序排最前的那份（`list_accounts` 的排序）。
- 已知未處理（審查提出，spec 未要求）：兩個不同帳號識別碼用了同一個標籤時報表會有兩欄同名；兩個 `report` 同時跑時對照的讀改寫沒有鎖，編號有機會撞號。
- 詞彙表落差：`GLOSSARY.md` 把「未監看帳號」限定為當前憑證帳號，報表卻用它稱呼歷史用量的帳號（票面與 spec 明文要求）。未改詞彙表，待使用者決定。
- 審查（兩軸＋變異）：Standards 無硬違規；採納 `resolve_labels` 改名 `update_labels`（它會寫檔）、示警用詞對齊詞彙表的「憑證快照已移除」、測試 helper 集中到類別開頭、拆開一個名字兩個主張的測試；未採納的判斷題：兩個 NamedTuple 與裸 dict、把合併邏輯搬進 `ManagedDirectory`（與 `update_ledger` 同形）。Spec 六條驗收逐條屬實。變異 10 個，7 個一開始轉紅、3 個全綠或偏薄（編號下限 `>= 1` 改 `>= 0`、同帳號兩份快照取後者、編號 `max+1` 改 `len+1`）——已補測試，並在暫存副本重跑那三個變異確認都轉紅。
