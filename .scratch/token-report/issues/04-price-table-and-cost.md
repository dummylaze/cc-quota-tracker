# 04: 單價表與估算金額

**What to build:** 報表依內建單價表估算金額。單價表隨版本發佈、執行時不連網（ADR-0013）；單價表沒有的模型照樣計入 token，金額標為未知。

**Blocked by:** 02

**Status:** resolved

## Acceptance criteria

- [x] 單價表是隨版本發佈的資料檔，記有版本日期；每個模型有 input、output、cache 寫入（5 分鐘、1 小時）、cache 讀取的單價，來源是供應商公開的定價
- [x] 金額在產生報表時用當下的單價表計算，不寫進任何紀錄
- [x] 單價表沒有的模型、或紀錄裡出現單價表無法計價的計費因素時，那部分金額記為未知：格子顯示「—」並附原因，合計標示含未知部分，頁首出現示警
- [x] 報表頁首顯示單價表的版本日期，並標明金額是估算
- [x] 打包好的 exe 帶有單價表，解壓縮後的命令列 exe 產生的報表有金額
- [x] 測試走命令列 `report --no-open`、跑在假 home 上，用測試專用的假單價表
- [x] 既有測試全部通過

## Comments

- 2026-10-21：**實作完成**。單價表是 `cc_quota_tracker/prices.json`（版本日期 2026-10-21，取自供應商定價頁 https://platform.claude.com/docs/en/about-claude/pricing），由 `prices.py` 讀；exe 經 spec 的 `datas` 放在 `_internal/cc_quota_tracker/` 底下。
- 使用者定案：金額格子顯示整數美元，滑鼠停留提示顯示到分；一格只有部分算不出時顯示「已知＋—」，全部算不出才顯示「—」；單價表不含的計費因素（fast mode、US-only 推論、非標準服務等級、web search 次數費、Haiku 5.5 prompt 超過 10 萬 token）一律記為未知，不計價；頁首、欄名、橫幅、頁尾註記照提案的字樣。
- 票面外、實作時自補的決定（審查者判斷皆合理）：
  - 計費因素用白名單判斷：`service_tier`、`speed`、`inference_geo` 不是標準值（缺欄位算標準），或 web search 次數 > 0，就記一個因素。值不是字串、或不像代碼時記成 other。
  - 帳本格子多兩個選填欄位：`factors`（沒有就不寫）與 `maxPrompt`（格子裡最長的 prompt）。沒有這兩個欄位的舊格子照讀，當成標準計費。
  - 長 prompt 在入帳前依單價表的門檻拆到另一格。入帳時單價表還沒有那個模型的門檻、之後才補上時，靠 `maxPrompt` 判斷：超過門檻的格子整格算不出（審查發現的靜默低估，已補測試）。
  - 單價表任何一處不合格就整份當成讀不到，所有金額未知，並以橫幅示警。
  - 模型識別碼查不到時，去掉 `-YYYYMMDD` 日期後綴再查一次。
  - 所有報表測試共用一份測試專用的假單價表（`ReportTestCase`）。
- 驗收「解壓縮後的命令列 exe 產生的報表有金額」：自動化的部分是 spec 結構測試。另外用 `packaging/requirements-build.txt` 實際建了一次 exe，把資料夾複製到別處，在假 home 上跑 `cc-quota-tracker-cli.exe report --no-open`：報表的單價表版本是 2026-10-21，合計金額 4.0（1M input × Opus 5.5 $4）。
- 驗收「頁首標明金額是估算」的落點：頁首 meta 顯示單價表版本日期，「估算」兩字在金額欄的欄名「估算金額（USD）」與頁尾註記（照定案的字樣與位置）。
- 畫面驗證（只改了陽春合計表：加金額欄與註記）：用無頭 Edge 截淺色／深色、中文／英文四張。高彩度面積 0.4～1.3%，留白率近似 79～90%。沒有新增顏色 token：新欄沿用數字格的文字色與卡片底色，新註記沿用附註色與底板，對比度沿用 token-report/02 的量測（最低 4.56:1，APCA 最低 |Lc| 60.1）。邊框仍是 1px，沒有漸層、Emoji 或左側彩色邊條。四張截圖中英兩版都放得進 960px。
- 審查（兩軸＋變異）：兩軸都指出計費欄位是 list／dict 時會丟 unhashable 例外、讓報表當掉，已修並補測試。Standards 另指出帳本被手改的長 prompt 因素（`²`）會讓報表當掉，以及上述長 prompt 靜默低估，皆已修並補測試。Spec 七條驗收中五條屬實；exe 一條是上面的人工驗證；「頁首標明估算」的落點見上。變異 8 個全部轉紅，我抽驗 `_long_prompt` 的 `>` 改 `>=`，確認轉紅。未採納：計費因素改成型別（目前只有這張票用到）、原因字串改由頁面在地化（帳號標籤也是在地化後才放進資料，維持一致）、示警跟著區間變（既有示警都是全域的）。
