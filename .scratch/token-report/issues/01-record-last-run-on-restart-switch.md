# 01: 重新啟動後偵測到的切換記下上一次運作時間

**What to build:** 本工具停止運作期間發生的切換，要等重新啟動才會被記下，這段停機期間的用量不知道屬於哪個帳號。從這張票起，重新啟動後第一輪就偵測到的切換，切換紀錄另外記下本工具上一次運作的時間，報表才能把那段標為未歸屬時段。這張票不依賴報表的其他部分，要盡早發佈：每晚一天上線，就多一天的停機時段無從辨識。

**Blocked by:** None (can start immediately)

**Status:** resolved

## Acceptance criteria

- [x] 重新啟動後第一次完成判定的那一輪偵測到切換時，該筆切換紀錄帶上一次運作時間，取自上一輪觀測裡的最後運作時間（讀不到當前憑證或上一輪觀測、因而沒有判定的輪次不算）
- [x] 執行中（不是重新啟動後第一次判定）偵測到的切換不帶這個欄位
- [x] 第一次運作（沒有上一輪觀測）照舊算一次切換，不帶這個欄位
- [x] 上一輪觀測沒有最後運作時間、或讀不懂時，照常記切換、不帶這個欄位
- [x] 重新啟動後沒偵測到切換時，照舊不寫任何切換紀錄
- [x] 舊格式的切換紀錄與上一輪觀測照舊可讀；寫不成時下一輪重試的行為不變
- [x] 測試經過 poll、跑在假 home 上，涵蓋上述各情形
- [x] 既有測試全部通過
- [x] 結案後提醒使用者發版

## Comments

- 2026-10-20：實作完成，`tests/test_switch_detection.py`（`RestartLastRunTest`）與 `tests/test_managed_directory.py` 涵蓋各驗收條件，全套測試通過。欄位名為 `lastRunAt`，放在 `switches.jsonl` 該筆紀錄上；舊行不動。
- 與票面字面的差異：票面寫「取自上一輪觀測裡的最後運作時間」。實作是在啟動後第一次讀到上一輪觀測時就把那個時間留在記憶體，判定到切換時才用。原因：沒有判定的輪次（讀不到當前憑證）仍會覆寫觀測檔裡的運作時間，若到判定輪才讀，會拿到那一輪留下的時間，不是停機前的時間。有對應測試（當前憑證一度讀不到、上一輪觀測一度鎖住）。
- 運作時間與上一輪觀測的其他欄位一次讀完（併進 `Observed`），避免同一個檔分兩次讀、第二次剛好被鎖住而讓這筆切換永久少記欄位。
- 命令列每次都新建核心，所以命令列的 poll 也算一次「重新啟動後第一輪」；看板沒在跑時，上一次運作時間可能是上一次命令列 poll 的時間。
- 已知限制：切換紀錄已寫成、觀測檔寫失敗時，下一輪會重記一次同一筆（帶同一個欄位），重複行不影響歸屬（既有行為）。
- 這張票要盡早上線，每晚一天就多一天的停機時段無從辨識：請使用者發版。
