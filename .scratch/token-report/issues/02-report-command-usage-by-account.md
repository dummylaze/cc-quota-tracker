# 02: 命令列 report：從對話紀錄算出各帳號用量

**What to build:** 使用者執行命令列 `report`，本工具解析 Claude Code 的對話紀錄、依切換紀錄把用量歸屬到帳號，產生一份本機 HTML 報表並用預設瀏覽器打開。這張票打通整條路徑：解析、去重、歸屬、未歸屬時段、示警、HTML 骨架與內嵌的報表資料；畫面先用一張陽春的合計表（分頁畫面在 06～08）。這張還沒有用量帳本與金額，每次都從對話紀錄重新計算。

**Blocked by:** None (can start immediately)

**Status:** resolved

## Acceptance criteria

- [x] 實作前用真實格式確認：同一則回應寫成多行時，output 是否逐行累積；依結果決定去重留哪一筆，並在 Comments 記下確認結果（不貼任何真實內容）
- [x] 實作前與使用者確認：`report` 的結束代碼各代表什麼（有示警但產生成功時算不算成功）、橫幅的字樣
- [x] `report` 產生報表並用預設瀏覽器打開；`report --no-open` 只產生並印出檔案路徑
- [x] 報表是單一 HTML，放在設定檔所在的目錄，每次覆寫；不載入任何外部資源；不含帳號識別碼與 email
- [x] HTML 內嵌一份報表資料（JSON），畫面由它算出
- [x] 讀取 Claude Code 目錄底下的對話紀錄（含子代理的紀錄），只取帶用量的回應，以訊息識別碼＋請求識別碼去重
- [x] 取用 input、output、cache 寫入（有 5 分鐘與 1 小時時分開）、cache 讀取
- [x] 用量依切換紀錄歸屬：t 之前（含）最後一筆切換紀錄所切到的帳號識別碼
- [x] 未歸屬：切換紀錄帶上一次運作時間時，該時間到切換時間之間；第一筆切換紀錄之前；切到帳號未知之後。合計時多一列未歸屬並計入合計
- [x] 第一筆帶上一次運作時間的切換紀錄之前的期間，報表加註記「無從辨識停機時段」
- [x] cache 命中比例依詞彙表的定義計算，報表附註算法
- [x] 按 UTC 時間計算、顯示時換算成本機的日；區間可選近 7 天、近 30 天、全部
- [x] 帳號依現有的綁定顯示帳號標籤；查不到標籤的先顯示為未監看帳號（編號規則在 05）
- [x] 對話紀錄結構認不得時計數並示警，不算成 0；切換紀錄讀不到時示警；錯誤印到 stderr
- [x] 頁首顯示產生時間；文字跟著設定的語系
- [x] 測試走命令列 `report --no-open`、跑在假 home 上，比對內嵌的報表資料；假對話紀錄照實測的欄位形狀造（多行同一回應、子代理、不認得的結構），不含真實內容
- [x] 既有測試全部通過

- 票面外、實作時自補的決定（審查時逐條請審查者判斷）：
  - 報表資料除 `rows`（日 × 帳號 × 模型）外，額外帶 `summary`（近 7 天、近 30 天、全部各自預算好的各帳號合計與 cache 命中比例）。理由：JS 裡的算術 Python 測不到，預算在 Python 才驗得到命中比例、區間起點與本機日界。
  - 「近 7 天」＝本機的今天加前 6 天（30 天同理）。用量先收成 UTC 小時、再換算成本機的日，與日後的用量帳本同粒度；非整點時區（如 +5:30）時一個 UTC 小時整個歸給小時起點所在的日。
  - 切換紀錄相鄰兩筆帳號與上一次運作時間都相同時只留第一筆（01 票 Comments 記的「寫失敗重記」），否則兩筆之間的幾秒會被誤標未歸屬。
  - 對話紀錄檔打不開（鎖住、權限）另計示警，不靜默少算；檔尾沒有換行、讀不懂的最後一行視為還在寫，不算結構不符。
  - 切換紀錄讀不到（檔案打不開）→ 一筆都不採用、全部未歸屬；個別行讀不懂 → 略過並計數；檔案不存在不是示警。

  - 未監看帳號依在切換紀錄首次出現的順序編成「未監看帳號 n」；編號跨次固定的規則屬 05。
