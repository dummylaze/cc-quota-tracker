# token 報表

Status: resolved

## 問題陳述（Problem Statement）

本工具顯示的是各帳號的額度百分比，看不到 token 數：總共用了多少、cache 命中多少、各模型各用了多少。token 數只存在 Claude Code 的對話紀錄裡，而對話紀錄有三個限制，讓使用者沒辦法自己算出「每個帳號」的用量：

- **對話紀錄不含帳號資訊**：每一則回應只記時間、模型與用量，不記是哪個帳號。能把用量歸屬到帳號的，只有本工具的切換紀錄（ADR-0003、ADR-0009）。
- **一天會切換好幾次，執行中的 session 也會跟著換帳號**（ADR-0011）：按日或按 session 彙總的數字切不開，只有逐筆比對時間才行。這也是現成的彙總工具派不上用場的原因（ADR-0013）。
- **Claude Code 會刪掉舊的對話紀錄**（依它的保留期限設定，預設 30 天）：過了期限，那段用量就再也算不出來。

另外，本工具停止運作期間發生的切換，要等重新啟動才會被記下。這段時間的用量其實不知道屬於哪個帳號，但目前的切換紀錄分辨不出這種情形。工具每輪只覆寫一個「最後運作時間」，事後無法還原哪些時段沒在運作。

## 解決方案（Solution）

本工具產生一份 token 報表，把用量依切換紀錄歸屬到帳號，並把算好的結果存成用量帳本，不受 Claude Code 刪除舊紀錄的影響。

- **從現在起記下未歸屬時段**：重新啟動後第一輪就偵測到的切換，切換紀錄另外記下本工具上一次運作的時間。這段停機期間的用量，報表標為未歸屬，不歸給任何帳號。
- **用量帳本**：懸浮視窗每天在背景啟動一次子行程，把對話紀錄算成「時間 × 帳號 × 模型」的 token 數追加進帳本；開報表時也會追加。只要在 Claude Code 刪掉對話紀錄之前追加過，那段用量就一直看得到。
- **報表**：一份本機 HTML，用預設瀏覽器打開，分成三個分頁（總覽、每日明細、帳號比較），可以選區間、選擇單看一個帳號或全部帳號合計。顯示合計 token、cache 寫入、cache 讀取、cache 命中比例、按模型細分，以及依內建單價表估算的金額。
- **不連網、不新增依賴**：自己用標準庫解析對話紀錄；單價表隨版本發佈，執行時不下載（ADR-0013）。
- **入口**：懸浮視窗的右鍵選單，以及命令列 `report`。

## 使用者故事（User Stories）

### 使用者：看報表

1. 身為持有多個帳號的使用者，我想從懸浮視窗的右鍵選單打開 token 報表，這樣不必開終端機也看得到用量。
2. 身為使用者，我想讓報表直接在預設瀏覽器打開，這樣不必另外找檔案。
3. 身為使用者，我想在報表的總覽一眼看到區間內的總 token、cache 命中比例與估算金額，這樣能馬上知道總共用了多少。
4. 身為使用者，我想看到每日用量的長條圖、依帳號分色堆疊，這樣看得出哪幾天用得多、用在哪個帳號。
5. 身為使用者，我想在每日明細看一張按日的表，點開某一天再看各模型，這樣能查到某一天的細節。
6. 身為使用者，我想在帳號比較看到每個帳號並排的一欄，合計在最前，這樣不必來回切換就能比較帳號。
7. 身為使用者，我想選擇近 7 天、近 30 天或全部，三個分頁共用同一個區間，這樣切換分頁時不必重選。
8. 身為使用者，我想在總覽和每日明細選擇單看某個帳號或看全部帳號合計，這樣能分開看工作與個人帳號。
9. 身為使用者，我想看到 cache 命中比例和它的算法，這樣知道這個數字代表什麼，不必猜。
10. 身為使用者，我想看到各模型的用量，這樣知道哪個模型用得最多。
11. 身為使用者，我想在合計、cache 寫入、cache 讀取之外，也能看到 input、output 等其他欄位，這樣需要時查得到完整數字。
12. 身為使用者，我想看到依內建單價表估算的金額，並知道單價表是哪一天的版本，這樣知道金額只是估算、可能已經過時。
13. 身為使用者，我想讓數字用萬、億表示（英文語系用 K、M、B），滑鼠停在數字上看到完整數值，這樣大數字好讀又不失精確。
14. 身為使用者，我想讓報表跟著我設定的語系顯示，這樣跟懸浮視窗用同一種語言。
15. 身為使用者，我想在報表上看到產生時間與帳本最後更新的時間，這樣知道數字新不新。

### 使用者：歸屬與未歸屬

16. 身為使用者，我想讓用量依切換的那一刻切開、歸給當時的當前憑證帳號，這樣一天切換好幾次也不會算錯。
17. 身為使用者，我想讓本工具停止運作期間發生切換的那段用量標為未歸屬，而不是被猜給某個帳號，這樣報表上歸給某帳號的數字都是可信的。
18. 身為使用者，我想在全部帳號合計時看到一列「未歸屬」並計入合計，單看一個帳號時則不列，這樣總數對得上，單一帳號的數字也不被灌水。
19. 身為使用者，我想讓切換紀錄開始之前的用量整段標為未歸屬，這樣不會有任何一段是猜的。
20. 身為使用者，我想在區間落在「開始記錄停機時段」之前時看到註記，這樣知道那段時間的歸屬無法辨識停機。
21. 身為使用者，我想讓已經移除的帳號仍以它最後用過的帳號標籤顯示，這樣移除憑證快照後，歷史用量不會變成無名的數字。
22. 身為使用者，我想讓從沒納管過的帳號顯示成「未監看帳號 1」「未監看帳號 2」，而不是顯示帳號識別碼或 email，這樣報表上不出現識別資訊。

### 使用者：帳本與保留期限

23. 身為使用者，我想讓本工具每天自動把用量記進帳本，這樣我不必記得定期開報表，也不會因為 Claude Code 刪掉舊紀錄而少掉一段。
24. 身為使用者，我想讓帳本在 Claude Code 刪掉舊對話紀錄之後仍保留那段用量，這樣報表能涵蓋全部歷程，不只最近 30 天。
25. 身為使用者，我想在報表上看到帳本最早有資料的日期，這樣知道更早的用量為什麼看不到。
26. 身為使用者，我想讓每日更新失敗時只記在錯誤紀錄、並在報表頂端看得到，懸浮視窗不跳提示，這樣不會被我無能為力的訊息打擾。
27. 身為使用者，我想讓開報表和每日更新同時發生時不會把帳本寫壞，這樣不必擔心時間撞在一起。

### 使用者：錯誤與例外

28. 身為使用者，我想在對話紀錄的結構認不得時看到橫幅，而不是看到 0，這樣不會誤以為那段時間沒用量。
29. 身為使用者，我想在切換紀錄讀不到時看到橫幅，這樣知道歸屬可能不完整。
30. 身為使用者，我想讓單價表沒有的模型照樣計入 token，金額格顯示「—」並附原因，這樣新模型出現時報表不會壞，也不會亂算金額。
31. 身為使用者，我想在報表頂端看到所有需要注意的事（未知模型、結構認不得、帳本更新失敗），這樣一個地方就能看完。

### 命令列與腳本

32. 身為命令列使用者，我想執行 `report` 產生報表並打開，這樣在終端機也能用。
33. 身為寫腳本的使用者，我想用 `report --no-open` 只產生報表並印出檔案路徑，這樣能在自己的流程裡處理它。
34. 身為寫腳本的使用者，我想讓錯誤印到 stderr、並以結束代碼區分結果，這樣腳本能判斷成功與否。

### 架設者與部署

35. 身為使用 exe 版的架設者，我想讓選單開報表和每日更新都不閃出主控台視窗，這樣使用體驗跟其他功能一致。
36. 身為架設者，我想讓報表不需要另外安裝任何東西、也不連網，這樣 exe 版解壓縮就能用，部署前的檢查不必多一項。
37. 身為架設者，我想讓報表內建、不必另外開啟，這樣升級後就有。
38. 身為架設者，我想讓報表 HTML 固定放在設定檔所在的目錄、每次覆寫，這樣知道去哪裡找，也不會越積越多。
39. 身為架設者，我想讓用量帳本放在納管目錄、跟切換紀錄一樣收緊權限，因為它含帳號識別碼。
40. 身為架設者，我想讓報表 HTML 裡不含帳號識別碼與 email，只含帳號標籤，這樣它可以放在權限沒收緊的位置。
41. 身為架設者，我想在 README（英文與正體中文）讀到報表的入口、資料來源、帳本位置、未歸屬的意思與金額只是估算，這樣能向使用者解釋數字。
42. 身為架設者，我想讓懸浮視窗的記憶體驗收不受報表影響，這樣報表的解析工作不會讓常駐視窗變重。

## 實作決策（Implementation Decisions）

### 切換紀錄：記下上一次運作時間

- 重新啟動後的第一輪就偵測到切換時，那筆切換紀錄多一個欄位：上一次運作的時間，取自上一輪觀測裡既有的最後運作時間。其他切換不帶這個欄位。
- 第一次運作（沒有上一輪觀測）算一次切換，但沒有上一次運作時間可記，所以不帶。
- 舊的切換紀錄沒有這個欄位，照舊可讀。報表把「第一筆帶這個欄位的紀錄」之前的期間視為「無從辨識停機時段」，照切換時間歸屬並加註記。
- 這一項要先發佈：每晚一天上線，就多一天的停機時段無從辨識。它不依賴報表的其他部分。

### 歸屬規則

- 某一則回應在時間 t 的用量，歸給 t 之前（含）最後一筆切換紀錄所切到的帳號識別碼。
- 那筆切換紀錄若帶有上一次運作時間 P，則 P 到該筆紀錄時間之間的用量是未歸屬時段。
- 第一筆切換紀錄之前的用量、以及切到「帳號未知」（識別碼為空）之後的用量，都是未歸屬。
- 停機期間帳號沒變（重新啟動後第一輪沒偵測到切換）的，不算未歸屬。停機期間切走又切回同一個帳號的情形不處理。

### 解析對話紀錄

- 來源是 Claude Code 目錄底下的對話紀錄（含子代理的紀錄），遞迴讀取，路徑沿用既有的 Claude Code 目錄設定。
- 只取帶用量的回應紀錄，以「訊息識別碼＋請求識別碼」去重：同一則回應會寫成多行。實作前先用真實格式確認 output 是否逐行累積，若是就留最後一筆。
- 取用的用量種類：input、output、cache 寫入（有 5 分鐘與 1 小時兩種時分開記）、cache 讀取。
- 結構認不得的紀錄不計為 0：計數後在報表與錯誤紀錄示警。

### 用量帳本

- 粒度是「UTC 小時 × 帳號識別碼（或未歸屬）× 模型」，每格存各種 token 數，不存金額。按 UTC 小時存，換時區或日光節約時間都不會錯位；顯示時再換算成本機的日。
- 只追加已經過去 24 小時以上、帳本裡還沒有的小時；最近 24 小時每次產生報表時從對話紀錄重新計算，不寫進帳本，避免遲到的紀錄被漏掉。
- 只追加不改寫。帳本另外記下最早有資料的時間與最後更新時間（含失敗原因）。
- 放在納管目錄的工具狀態裡，收緊權限的方式比照切換紀錄。
- 同一時間只讓一個行程寫帳本；另一個等它寫完或跳過這次追加，報表照樣用帳本加上最近 24 小時產生。

### 帳號標籤的對照

- 報表另外保存一份「帳號識別碼 → 最後用過的帳號標籤」，每次產生時依現有的綁定更新；憑證快照移除後仍沿用最後的標籤。這份對照含帳號識別碼，跟帳本放在一起、一樣收緊權限。
- 從沒有綁定過的帳號識別碼，依首次出現的順序編成「未監看帳號 n」，編號存在同一份對照裡，之後不變。

### 單價表與金額

- 單價表是隨版本發佈的資料檔，來源是供應商公開的定價，記有版本日期；每個模型各有 input、output、cache 寫入（5 分鐘、1 小時）、cache 讀取的單價。
- 金額在顯示時用當下的單價表算，所以單價表更新後舊資料不必重寫。
- 單價表沒有的模型，或紀錄裡出現單價表無法計價的計費因素時，那部分的金額記為未知：格子顯示「—」並附原因，合計標示含未知部分。

### cache 命中比例

- cache 讀取 ÷（input＋cache 寫入＋cache 讀取）。output 不計。報表上附註算法：供應商沒有公布這個比例的算法，這是依供應商「總 input＝三者相加」的定義推得的。

### 報表 HTML

- 單一檔案，放在設定檔所在的目錄，每次產生就覆寫；不載入任何外部資源（字型、圖表都內嵌），不自動刷新。
- 內嵌一份報表資料（JSON），三個分頁都從它算出畫面。測試只比對這份資料。
- 內容只含帳號標籤，不含帳號識別碼與 email。
- 頁首：產生時間、帳本最後更新時間、帳本最早有資料的日期、單價表版本日期、需要注意的事項橫幅；區間選擇（近 7 天、近 30 天、全部）；單看或合計的選擇（帳號比較分頁本身就是並排，不受這個選擇影響）。
- 三個分頁：
  - **總覽**：總 token、cache 命中比例、估算金額三個總數；每日長條圖依帳號分色堆疊（單看一個帳號時不堆疊，只用該帳號的顏色）；各模型的表，其他欄位可展開。
  - **每日明細**：按日的表，點日期展開各模型，最後一列是區間合計。
  - **帳號比較**：每個帳號一欄，合計在最前，未歸屬單獨一欄；每欄附小長條圖，各模型與其他欄位收在摺疊區。
- 顏色只代表帳號；同一個顏色不拿來表示模型或其他意義。
- 數字格式：正體中文用萬、億，英文用 K、M、B；完整數值放在滑鼠停留提示裡。
- 文字跟著設定的語系。

### 入口與部署

- 命令列新增 `report`：產生報表並用預設瀏覽器打開；加 `--no-open` 時只印出檔案路徑。錯誤印到 stderr，以結束代碼區分。
- 另有一個不寫進說明的參數，只更新帳本、不產生 HTML，給每日更新用。
- 懸浮視窗的右鍵選單新增「token 報表」：在背景啟動子行程產生報表，再用預設瀏覽器打開。
- 懸浮視窗啟動後，以及之後每 24 小時，在背景啟動一次只更新帳本的子行程。失敗寫進錯誤紀錄，懸浮視窗不提示。
- 子行程不顯示主控台：exe 版呼叫命令列的 exe，原始碼版呼叫 `python -m`。
- 報表與帳本更新都在子行程裡跑，懸浮視窗的記憶體驗收（ADR-0004）不受影響；子行程不受那個上限約束。
- 不新增設定，不新增網路呼叫，不新增第三方套件。

## 測試決策（Testing Decisions）

- 好的測試只驗外部行為：給定對話紀錄、切換紀錄、帳本與單價表，報表資料長什麼樣、結束代碼與 stderr 是什麼；不驗內部函式怎麼切。
- **主接縫：命令列 `report --no-open`，跑在假 home 上**。放進假的對話紀錄、切換紀錄、單價表，執行後讀出 HTML 內嵌的報表資料比對。去重、歸屬、未歸屬時段、帳本追加與沿用、最近 24 小時重算、金額與未知模型、標籤對照、各種錯誤橫幅，全部從這一層驗。前例：既有命令列測試在同一個行程裡呼叫命令列入口的寫法。
- **切換紀錄的新欄位：經過 poll，跑在假 home 上**。重新啟動後第一輪偵測到切換時才帶上一次運作時間；沒偵測到切換、或第一次運作時不帶。前例：既有的切換偵測測試。
- **懸浮視窗的選單與每日觸發**：選單有「token 報表」；啟動時與每 24 小時啟動一次只更新帳本的子行程。子行程以假的取代，只驗呼叫時機與參數。前例：既有懸浮視窗查詢額度的測試。
- **測試用的假對話紀錄照實測的欄位形狀造**：同一則回應寫成多行、output 可能逐行累積、含子代理的紀錄、含不認得的結構。只取結構，不放任何真實內容；憑證一律用假的。
- 時間一律用可控時鐘，涵蓋跨 UTC 日界、本機時區換算、24 小時邊界。
- 畫面三個分頁不寫自動化測試，以審美驗證（對比度、留白、高彩度面積等量測，兩種主題）加上人工驗收；審美驗證列在每張畫面票的驗收條件裡。

## 範圍外（Out of Scope）

- 按週窗口或工作階段窗口切報表（目前只按日；帳本按小時存，以後做得到）。
- 呼叫外部報表工具、執行時下載單價表、任何網路呼叫。
- 報表自動刷新、懸浮視窗上的帳本狀態提示。
- 按專案切分用量。
- 匯出 CSV 或 JSON 的公開格式。
- 補辨識「開始記錄上一次運作時間」之前的停機時段。
- 其他供應商的用量（另一個里程碑）。
- 修改或刪除帳本內容的功能。

## 補充說明（Further Notes）

- 原型在本機分支 `prototype/token-report`（未推送），用 `?variant=A|B|C` 切換三種版面；A、B、C 分別對應總覽、每日明細、帳號比較。原型是假資料、假單價，版面細節以本 spec 為準。
- 切票建議：記下上一次運作時間的票排第一、可以單獨發佈；接著是帳本與報表資料（含命令列 `report`），再來是三個分頁各一張，依總覽 → 每日明細 → 帳號比較的順序依賴；選單與每日觸發、README 可以各自一張。
- 實作前與使用者確認：`report` 的結束代碼各代表什麼（有橫幅但產生成功時算不算成功）、分頁與橫幅的字樣、帳號的配色、數字格式在哪個量級換單位。
- 相關決策：ADR-0003、ADR-0009（切換紀錄）、ADR-0004（記憶體上限只約束懸浮視窗）、ADR-0011（執行中的 session 會跟著切換）、ADR-0012（exe 的兩個執行檔）、ADR-0013（自己解析、單價表隨版本發佈）。
