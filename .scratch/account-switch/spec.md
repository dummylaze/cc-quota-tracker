# 切換帳號

Status: resolved

## 問題陳述（Problem Statement）

使用者有多個 Claude 帳號（例如工作／個人），本工具已經能同時監看它們的額度，但要換帳號時，只能回到 Claude Code 執行 `/login`、走一次瀏覽器登入流程。每換一次都要重新登入，而且換過之後，被換走的那個帳號原本交給本工具保管的憑證快照常常就不能用了。

實際觀察到三件事，讓「把憑證快照複製回去」這個直覺做法行不通：

- **刷新會輪替憑證**：Claude Code 每次刷新都換一組新的 refreshToken，舊的立即作廢。所以一份憑證快照只要它的帳號當過當前憑證帳號、被刷新過一次，就成了廢檔。現在的工具在這種情況會讓「憑證快照已失效」一直亮著，待命帳號的到期倒數也照樣顯示為有效，使用者看不出它其實已經不能用了。
- **只換憑證會錯配**：Claude Code 把用量歸給誰，看的是帳號資訊，不是憑證。只換憑證、不換帳號資訊，執行中的 session 會用新帳號的額度，畫面上和額度快取卻記在舊帳號名下。
- **執行中的 session 會跟著換**：當前憑證被換掉之後，已經開著的 Claude Code session 會改用新的憑證，不需要重新啟動。這讓工具內切換變得可用，但也代表寫錯一次，影響會立刻出現在使用者正在用的 session 上。

另外，「納管帳號」這個詞同時指「畫面上有它的卡片」和「可以切換過去」，兩者在切換功能出現之後不再相同（例如憑證快照過期、或舊版納管的快照沒有帳號資訊），畫面需要說清楚哪些帳號能切、哪些不能、為什麼。

## 解決方案（Solution）

本工具可以從右鍵選單或命令列切換到另一個納管帳號，並且讓憑證快照不再因為刷新而作廢。

- **憑證同步**：當前憑證被刷新後，本工具把新憑證寫回出自同一次登入的那份憑證快照（ADR-0011）。判斷「同一次登入」只看 refreshToken 的到期時間：相差 60 秒內、而且只有一份快照符合才寫。本工具沒在執行時發生的刷新，下次啟動也補得上。
- **切換**：寫入目標帳號的憑證快照，並且只改寫帳號資訊這一個鍵，其他內容一律不動。切走之前先同步一次、保存切換前憑證；寫入前後各替舊帳號、新帳號查一次額度，後者兼作驗證。
- **還原上一次切換**：用切換前憑證回到切換之前的狀態，只保留最近一份。
- **監看帳號分兩類**：能切換過去的是**納管帳號**；其他（沒有帳號資訊、過期、失效、寫回失敗）是**僅監看帳號**，照常顯示讀數與到期倒數，卡片附上不能切換的原因，補救一律是在 Claude Code 登入該帳號後重新納管。
- 本工具不提供任何以額度為觸發條件的自動切換（ADR-0005）；命令列的 `--yes` 只是讓使用者能從自己的腳本呼叫。

## 使用者故事（User Stories）

### 使用者：從看板切換

1. 身為使用者，我想在看板的右鍵選單找到「切換帳號」子選單，從工具內就換到另一個帳號，不必回 Claude Code 重新登入。
2. 身為使用者，我想在「切換帳號」子選單裡看到依序列出的待命帳號（以帳號標籤顯示），直接點選要切過去的那一個。
3. 身為使用者，我想在三種版面上都從同一個右鍵選單切換，不因為換了版面就找不到。
4. 身為使用者，我不想在卡片上看到切換按鈕，避免誤點就把正在用的帳號換掉。
5. 身為使用者，點選之後我想看到一個確認對話框，上面寫著目標帳號的標籤與憑證快照的到期倒數，確認之後才真的切換。
6. 身為使用者，我只想要一個確認對話框、沒有倒數延遲，確認就立刻開始。
7. 身為使用者，我想在確認對話框裡讀到這次切換的後果：目前的帳號是監看帳號時，它的憑證會先同步回它的快照；目前的帳號是未監看帳號時，它的憑證只會存成切換前憑證，而且只留最新一份。

## 實作決策（Implementation Decisions）

### 詞彙與分類

- 依 `GLOSSARY.md` 的新詞條：**監看帳號**＝**納管帳號**＋**僅監看帳號**；原「未納管帳號」改名**未監看帳號**；原「使用中帳號」改名**當前憑證帳號**（英文仍是 Active Account）。程式碼中對應的型別、角色、字串鍵一併改名，畫面與 README 的用字（兩種語言）同步更新。
- 納管帳號的條件：憑證快照經納管動作建立、附有帳號資訊、沒有過期、沒有失效、沒有寫回失敗（含重試中）。其餘監看帳號都是僅監看帳號，並帶一個原因：`沒有帳號資訊`／`已過期`／`已失效`／`寫回失敗（重試中 n/3）`／`寫回失敗（已停止重試）`。同時符合多個原因時，卡片只顯示一個，順序由實作票決定並寫進票裡。
- 看板模型（Board）的每張卡片多帶「能不能切換」與「不能切換的原因」；三種版面與 `list` 的文字輸出都從同一份資料渲染。

### 納管目錄

- 納管時從帳號資訊取得帳號識別碼並綁定（沿用既有綁定），同時把整份帳號資訊和憑證快照存在一起，同樣收緊權限。帳號資訊只保存、不顯示。
- 匯入或直接放進目錄的憑證檔沒有帳號資訊，是僅監看帳號。
- 新增**切換前憑證**的保存位置：只有一份，內容是切換當下的當前憑證與帳號資訊；每次切換（含還原）都覆寫。它不是憑證快照，不產生卡片、不讓任何帳號成為監看帳號。
- 失效旗標改為持久化：保留到該帳號被重新納管為止，不再在離開該帳號時清掉。同一個帳號識別碼綁了多份憑證快照時，只標到期最晚的那一份（沿用既有規則）。
- 寫回失敗的重試次數需要跨輪記住，並在下一次輪替（當前憑證的指紋改變）時重新計數。
- 所有寫入走既有的原子寫入與權限收緊路徑；`observed.json` 與切換紀錄的既有格式向下相容，舊檔可直接沿用。

### 憑證同步

- 規則：當前憑證的 refreshToken 到期時間跟某份憑證快照相差 60 秒以內、且只有一份符合，就判定出自同一次登入；當前憑證的指紋跟那份快照不同時，把當前憑證寫回那份快照。兩份以上符合時不寫。不看事件先後。
- 執行時機：GUI 每輪 poll 跑一次；命令列 `switch` 在寫入前跑一次；`list`、`query`、`add`、`remove` 不跑。
- 寫回失敗：每輪 poll 重試一次，最多 3 次；期間該帳號是僅監看帳號；成功即恢復；3 次都失敗就停止重試、改提示重新納管。
- 失效判定：某帳號當上當前憑證帳號時（依帳號資訊的帳號識別碼），當前憑證跟它綁定的快照找不到同一次登入的證據，就標為失效。刷新造成的差異由同步補上，不算失效。
- 判斷切換仍依 ADR-0009：指紋改變但帳號資訊仍是同一個帳號，不算切換。指紋只用來判斷「當前憑證和某份快照是否相同」。

### 切換

- 核心新增兩個入口：切換到某個帳號標籤、還原上一次切換。兩者回傳一個結果值，區分「拒絕（沒寫任何檔）＋原因」「成功」「已寫入但驗證失敗」，以及舊帳號查詢有沒有失敗；GUI 與命令列都只依這個結果呈現。
- 步驟順序：
  1. 檢查目標：標籤不存在、目標是僅監看帳號（含過期）、目標就是當前憑證帳號 → 拒絕，不寫任何檔。還原時，沒有切換前憑證或它已過期 → 拒絕。
  2. 同步當前憑證；當前憑證帳號是監看帳號、而同步失敗 → 拒絕。
  3. 替舊帳號查詢額度（讀數沒有落後、或舊帳號沒有綁定時跳過）；失敗不影響切換。
  4. 保存切換前憑證（當前憑證＋當下的帳號資訊）。
  5. 寫入目標的憑證快照到當前憑證；讀出 Claude Code 的設定檔、只改帳號資訊那一個鍵、整份寫回。讀出到寫回之間盡量短，不得用任何先前讀到的版本整份覆蓋。
  6. 以寫入時間追加切換紀錄（目標帳號的帳號識別碼）；之後的 poll 偵測到同一次切換不再重複追加。
  7. 替新帳號查詢額度，兼作驗證；失敗即「已寫入但驗證失敗」。
- 切換觸發的兩次查詢不啟動手動查詢的冷卻，但算進自動查詢的間隔（ADR-0010 修訂段）。
- 不檢查 Claude Code 的刷新鎖檔；GUI 與命令列之間不加鎖，以後寫入的為準。

### GUI

- 右鍵選單新增「切換帳號」子選單：依序列出待命帳號（以帳號標籤顯示），僅監看帳號不可選；最後一列是「還原上一次切換」，沒有可還原時反灰。卡片上不加切換入口。
- 確認對話框：目標標籤、目標快照的到期倒數、後果說明（當前帳號是監看帳號／未監看帳號兩種情境），當前帳號失效時加上那一行提示；不顯示任何額度數字。
- 切換中：整個視窗蓋一層半透明圖層，右鍵無效、可以拖動、不能取消；展開模式在圖層上顯示目前步驟。切換在背景執行，不阻塞視窗的事件迴圈（沿用查詢額度的背景執行做法）。
- 結果：成功不提示；驗證失敗顯示提示，問要不要還原上一次切換（是／否），按「是」直接還原、不再確認；舊帳號查詢失敗不提示；拒絕時顯示原因。

### 命令列

- 新增 `switch <帳號標籤>`、`switch --previous`，兩者都接受 `--yes`。
- 沒帶 `--yes` 時：標準輸入是終端機就顯示確認內容並詢問；不是終端機就印用法說明到 stderr、結束代碼 2，不寫任何檔。
- 結束代碼：0 成功／1 拒絕且沒寫任何檔／3 已寫入但驗證失敗／2 用法錯誤或無法確認。

## 測試決策（Testing Decisions）

- **好的測試只驗外部行為**：從核心的公開入口（poll、納管、移除、切換、還原）打進去，斷言看板內容、結果值，以及假 home 裡的檔案內容；不驗內部函式、不驗中間狀態的資料結構。
- **接縫（已與使用者確認，全部沿用現有的，不新增）**：
  1. **核心＋假 home＋假時鐘＋假 `claude`**——主接縫。憑證同步（60 秒容許、唯一符合、兩份符合不寫、離線期間補抄、寫回失敗重試與計數重置）、分類與原因、失效旗標的持久化、切換全流程、還原、切換前憑證、切換紀錄不重複、兩次查詢的跳過／失敗／冷卻與自動查詢間隔，都在這一層驗。
  2. **命令列 `main()`**——`switch`／`switch --previous`／`--yes`、非終端機沒帶 `--yes`、四種結束代碼、`list` 的原因與補救指令、`--help`。
  3. **視窗＋真的核心**——「切換帳號」子選單內容與反灰、確認對話框的內容（含失效那一行、不含額度數字）、切換中的圖層（右鍵無效、可拖動）、驗證失敗提示的「要還原嗎」。
- **必測的檔案不變式**：
  - 切換只改當前憑證與帳號資訊那一個鍵；Claude Code 設定檔的其他鍵（含在切換開始後才被寫入的內容）逐字保留。
  - 任何「拒絕」路徑之後，當前憑證與 Claude Code 設定檔的位元組完全不變。
  - 寫回的憑證快照、帳號資訊、切換前憑證都是收緊權限（沿用既有的 ACL 斷言輔助）。
- **憑證一律用假值**：測試只用假 home 裡產生的假憑證與假帳號資訊，不讀真實的使用者目錄。
- **前例（prior art）**：切換偵測與失效旗標的測試（`test_switch_detection`）、納管與權限（`test_manage_accounts`、`test_untightened`）、到期倒數（`test_credential_expiry`）、命令列（`test_cli`、`test_cli_query`）、查詢額度與自動查詢（`test_usage_query*`、`test_auto_usage_query`）、視窗與查詢入口（`test_widget`、`test_widget_query`）。共用骨架是 `tests/fakehome.py` 的 `HomeTestCase` 與 `tests/fake_claude.py`。

## 範圍外（Out of Scope）

- 任何以額度為觸發條件的自動切換（ADR-0005，是範圍邊界）。
- 加密憑證快照（含 DPAPI）；維持收緊權限、不加密（ADR-0007）。
- 依帳號識別碼自動重新納管、自動補存帳號資訊；舊版快照一律等使用者重新納管。
- 卡片上的切換按鈕；多於一層的還原歷史。
- 檢查 Claude Code 的刷新鎖檔；GUI 與命令列之間的鎖。
- 顯示 email 或任何帳號資訊的內容。
- 打包成 exe（另一個 feature）。
- 設定置頂卻沒有置頂的問題（另外開票）。
- token 報表、其他供應商、macOS／Linux、查詢待命帳號。

## 補充說明（Further Notes）

- **已驗證的前提**：「同一次登入裡，refreshToken 的到期時間在輪替前後只差一兩秒」已在三條輪替鏈上觀察過（兩條強迫刷新、一條自然刷新），最大差距約 1.2 秒；60 秒的容許範圍留有餘裕。憑證同步的票不必再等驗證。
- **待觀察、不影響設計**：refreshToken 到期之後，Claude Code 是否真的要求重新登入，目前未知。到期仍依快照記錄的時間判定「過期」。
- **現有缺陷的歸宿**：待命帳號的到期倒數在快照已作廢時仍顯示有效——由新分類吸收（舊快照沒有帳號資訊，升級後是僅監看帳號）並由憑證同步根治；當前憑證帳號第一次刷新後「憑證快照已失效」一直亮著——由憑證同步修掉。修之前先找出引入它們的 commit。
- **開票提醒**：改名波及面大（`ManagedAccount` 一系約 26 處、`unmanaged` 一系約 55 處），建議改名獨立成第一張票，不夾帶行為改動。帳號資訊的保存、僅監看的分類與顯示、切換本體不必等憑證同步；憑證同步與失效旗標的改動彼此相依。
- **實作前要跟使用者確認的細節**：僅監看帳號在子選單裡是反灰列出還是不列出；同時符合多個原因時卡片顯示哪一個；切換中圖層各步驟的字樣；命令列互動確認的提示文字。
