# 11: 切換中的半透明圖層

**What to build:** 確認切換之後，整個視窗蓋上一層半透明圖層，直到切換跑完或明確失敗為止。切換中右鍵選單打不開，但仍然可以拖動視窗；切換不能取消。展開模式下，圖層上顯示目前進行到哪一步。

**Blocked by:** 10

**Status:** resolved

- [x] 切換開始時蓋上圖層，結束（成功、驗證失敗、拒絕）時移除
- [x] 切換中右鍵選單打不開
- [x] 切換中仍然可以拖動視窗
- [x] 沒有取消的入口
- [x] 展開模式在圖層上顯示目前步驟（同步、查詢舊帳號、寫入、查詢新帳號）；精簡模式不顯示步驟
- [x] 各步驟的字樣（中英文）：實作前已與使用者確認（見 Comments）

## Comments

### 實作時定案（2026-10-06）

- **實作前與使用者確認**：①步驟字樣用「動詞＋對象＋省略號」：「同步目前帳號的憑證…」「查詢舊帳號的額度…」「寫入「{標籤}」的憑證…」「查詢新帳號的額度…」，只有寫入那一步帶目標標籤，沒有總標題；②舊帳號的查詢被跳過時，圖層直接不顯示那一步，不會一閃而過。英文版是 AI 自補，照中文同義翻譯（`switch.step.*`）。
- **核心的進度回報**（票 10 交接說「核心一次回傳、沒有進度回呼」）：`Core.switch(label, on_step=None)` 在每個步驟開始之前呼叫一次 `on_step(SwitchStep)`，呼叫發生在切換所在的執行緒。目標檢查就被拒絕時一次都不呼叫；舊帳號查詢被跳過時不回報 `QUERY_OLD`。視窗的背景執行緒只把最新的步驟記下來，主執行緒每 100 毫秒看一次，不必加鎖。
- **圖層的做法**：`cc_quota_tracker/switch_overlay.py`。視窗用透明色鍵，沒有真正的 alpha 可用，所以半透明以 canvas 的點陣填色（`stipple gray50`，面板色）蓋住視窗的圓角外形；展開模式在正中央放一塊卡片色底、前景色的步驟文字。圖層的 item 每次整批刪除重建，所以一定在最上面；版面重畫（換模式、語系、主題、版面）之後 `_apply` 末端會再蓋一次。點擊落在圖層上，底下的「更新」與摺疊區標題收不到；拖動與雙擊走視窗的綁定，照常運作。
- **結束時**：`_check_switch` 取到結果、`refresh()` 之前先拿掉圖層，所以之後那一輪 poll 出錯也不會讓圖層殘留（審查的變異檢查抓到這行原本沒有測試，已補）。
- **AI 自補**：切換中雙擊（精簡／展開互換）沒有擋，圖層跟著模式增減步驟文字；`toggle_mode` 只寫工具自己的設定檔、不碰核心，不違反 ADR-0006 與票 10 的「核心非執行緒安全」前提。若要擋，是一行守衛。`switch_overlay` 另寫了一份圓角折線的計算（與各版面的 `rrect` 同形）：版面彼此不共用的理由不適用於新模組，但也沒有為此重構三個版面。
- **審美驗證**：本票有畫面改動，已跑 `版面量測腳本` 與圖層實拍（三版面 × 兩主題 × 兩模式）。留白率最低 59.7%（版面 C 展開）、高彩度面積最高 4.2%、步驟文字對卡片底的對比 16.83:1（淺）／12.76:1（深），APCA Lc 103.8／92.3；沒有新增 token、沒有新色、沒有新字型。
- 未涵蓋、只能目測：Windows 高 DPI 下 `gray50` 點陣可能呈現棋盤紋。

### 給 12、09 的交接

- **12**：驗證失敗的提示仍掛在 `Widget._check_switch`（`VERIFY_FAILED` 目前直接回傳不提示）；圖層在那之前已拿掉。還原也會是一次切換，若它走同一條背景執行路徑，圖層與步驟字樣會直接沿用；還原的步驟與切換不同的話，要擴充 `SwitchStep` 與 `switch.step.*`。
- **09**：命令列的互動確認與本票無關；`Core.switch` 多了 `on_step`，命令列不傳。
