# 09: 命令列互動確認

**What to build:** 在終端機裡執行 `switch <帳號標籤>` 或 `switch --previous` 而沒帶 `--yes` 時，先顯示和 GUI 確認對話框相同的內容，使用者回答確認之後才切換。不是在終端機裡執行、又沒帶 `--yes` 時，照舊結束代碼 2、不寫任何檔。

**Blocked by:** 06, 08

**Status:** resolved

- [x] 標準輸入是終端機時：顯示目標帳號標籤與它的快照到期倒數，以及這次切換的後果：目前帳號是監看帳號時，它的憑證會先同步回它的快照；是未監看帳號時，它的憑證只會存成切換前憑證，而且只留最新一份
- [x] 目前帳號的快照已失效時，多顯示一行：「目前帳號快照已失效；用「還原上一次切換」，或在 Claude Code 重新登入後再重新納管。」
- [x] 不顯示任何額度數字
- [x] 回答確認才切換；回答否定時不寫任何檔，結束代碼 1
- [x] 不是終端機、沒帶 `--yes` → 用法說明印到 stderr、結束代碼 2，不寫任何檔
- [x] 詢問的提示文字（含肯定／否定怎麼回答）：**實作前與使用者確認**（見 Comments）

## Comments

### 實作時定案（2026-10-06）

**實作前與使用者確認**：

- 提示文字 `繼續？[y/N] `（英文 `Continue? [y/N] `）。只有 `y`／`yes`（不分大小寫、前後空白不計）算確認；直接按 Enter、「是」、其他任何輸入、EOF 一律是否定。兩種語系都只認 `y`／`yes`。
- 標籤不存在、僅監看帳號、已是當前憑證帳號這類「確認了也只會被拒絕」的請求，在詢問**之前**就拒絕（印原因、結束代碼 1），不顯示確認內容。

**實作時補的（未逐條問過）**：

- 否定回答印「已取消，沒有切換。」到 stderr、結束代碼 1（票面只寫結束代碼）。在提示上按 Ctrl-C 同樣當成否定，不丟 traceback。
- 預判用核心新增的公開入口 `Core.preflight_switch(label)`（`label` 是 `None` 就是還原）：跑一輪不自動查詢的 poll，回傳看板與目標檢查的結果。它不做任何切換的寫入，但 poll 本來就會做的維護（綁定檔清理等）照舊，所以不是純讀取。真正切換時核心會再判斷一次，以那一次為準。確認內容用的看板就是這一輪的。
- 確認內容直接呼叫 `fmt.switch_confirmation`／`fmt.restore_confirmation`（沒有另寫一份），後面空一行接提示。還原也一樣先問，內容是還原的確認框。
- `--help` 的寫法改成 `switch <帳號標籤> [--yes]`、`switch --previous [--yes]`，結束代碼說明改為「拒絕或回答否定 1」「不在終端機裡又沒帶 `--yes` 為 2」。重複的 `--yes` 是用法錯誤。

**審查（2026-10-06）**：Standards 沒有硬違規；Spec 無缺漏，變異檢查 15 個中 3 個全綠，其中 2 個補了測試（重複 `--yes`、預判不得啟動自動查詢），1 個行為上等價（預判拒絕後仍呼叫核心，核心會得到同一個拒絕）。

**字樣定案（2026-10-06，使用者回覆）**：失效那一行以票面與 spec 為準——「在 Claude Code 重新登入後再重新納管」。原本共用字樣（票 10 定稿）少了「重新」，已改共用的語系字串，GUI 確認對話框一起變；英文版本來就是 "sign in again"，不用動。
