# 02: 納管時保存帳號資訊，看板與 `list` 分出納管帳號與僅監看帳號

**What to build:** 納管時把整份帳號資訊跟憑證快照存在一起，權限一樣收緊，只保存、不顯示。看板的每張卡片多帶「能不能切換」與「不能切換的原因」：附有帳號資訊、沒有過期、沒有失效的是**納管帳號**，其餘是**僅監看帳號**，原因包括 `沒有帳號資訊`、`已過期`、`已失效`。`list` 的文字輸出會為每個僅監看帳號列出原因，以及重新納管的指令。舊版納管的快照、匯入的憑證檔、直接放進納管目錄的憑證檔，都因為沒有帳號資訊而是僅監看帳號。

**Status:** resolved

- [x] 帳號資訊（含 email）不出現在看板、畫面或命令列的任何輸出上
- [x] 匯入的憑證檔、直接放進目錄的憑證檔、舊版納管（沒有帳號資訊）的快照都是僅監看帳號，原因是「沒有帳號資訊」
- [x] 憑證快照的 refreshToken 已過期 → 僅監看帳號，原因是「已過期」；快到期但還沒過期 → 仍是納管帳號

- [x] 重新納管之後，該帳號回到納管帳號
- [x] 同時符合多個原因時，看板只帶一個原因。**實作前與使用者確認**優先順序，確認後寫進本票的 Comments

- [x] 看板模型對三種版面與 `list` 是同一份資料（版面上的顯示由 `03-watch-only-on-cards.md` 做）

## Comments

### 既有缺陷（2026-10-05，切票時記）

待命帳號的快照已經作廢時，到期倒數仍顯示有效。本票的新分類會吸收這個問題：舊快照沒有帳號資訊，升級後是僅監看帳號。根治要等憑證同步（`04-credential-sync.md`）。**修之前先對出問題的行跑 `git blame`，找出引入它的 commit。**

### 實作前與使用者確認（2026-10-06）

- 同時符合多個原因時，看板只帶一個，優先順序：**已過期 > 已失效 > 沒有帳號資訊**。
- `list` 為每個僅監看帳號印兩行縮排文字：原因一行、補救（重新納管的指令）一行；納管帳號不印。

### 結案說明（2026-10-06）

- 帳號資訊一個標籤一個檔，存在 `.state/account-info/`；是否「附有」看帳號資訊的帳號識別碼是否等於憑證快照綁定的帳號識別碼，所以手動換掉憑證快照的內容時，舊的帳號資訊不會被沿用。
- 沒有帳號資訊的納管（匯入、讀不到帳號識別碼）會刪掉同標籤原有的帳號資訊；移除憑證快照時一併清掉。
- 看板每張卡片新增 `switchable` 與 `watch_only_reason`；納管帳號的當前憑證帳號 `switchable` 也是 True（這是分類，不是「可以當切換目標」）。
- 「已失效」沿用既有的 `snapshot_invalid`（只有當前憑證帳號會被標）；旗標的持久化與寫回失敗的原因由 `04-credential-sync.md`、`05-writeback-retry.md` 做。
- README 兩版的「不讀取也不顯示 email」改成「不顯示；帳號資訊與憑證快照一起保存、權限收緊、不顯示也不外送」。
- 已過期的帳號在 `list` 會同時出現既有的 `snapshot.relogin` 行與新增的原因／補救行，內容重複；整併留給 `03-watch-only-on-cards.md`。
- 兩個舊測試因行為改變而調整：email 現在刻意存進帳號資訊檔（改成驗證只存在那裡）；移除憑證快照多了一次刪帳號資訊檔，故障注入改成只針對憑證快照路徑。
