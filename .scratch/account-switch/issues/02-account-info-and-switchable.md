# 02: 納管時保存帳號資訊，看板與 `list` 分出納管帳號與僅監看帳號

**What to build:** 納管時把整份帳號資訊跟憑證快照存在一起，權限一樣收緊，只保存、不顯示。看板的每張卡片多帶「能不能切換」與「不能切換的原因」：附有帳號資訊、沒有過期、沒有失效的是**納管帳號**，其餘是**僅監看帳號**，原因包括 `沒有帳號資訊`、`已過期`、`已失效`。`list` 的文字輸出會為每個僅監看帳號列出原因，以及重新納管的指令。舊版納管的快照、匯入的憑證檔、直接放進納管目錄的憑證檔，都因為沒有帳號資訊而是僅監看帳號。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `add` 從帳號資訊取得帳號識別碼並綁定（沿用既有做法），同時保存整份帳號資訊；檔案權限跟憑證快照一樣收緊（用既有的 ACL 斷言輔助驗）
- [ ] 帳號資訊（含 email）不出現在看板、畫面或命令列的任何輸出上
- [ ] 匯入的憑證檔、直接放進目錄的憑證檔、舊版納管（沒有帳號資訊）的快照都是僅監看帳號，原因是「沒有帳號資訊」
- [ ] 憑證快照的 refreshToken 已過期 → 僅監看帳號，原因是「已過期」；快到期但還沒過期 → 仍是納管帳號
- [ ] 快照被標為失效 → 僅監看帳號，原因是「已失效」
- [ ] 重新納管之後，該帳號回到納管帳號
- [ ] 同時符合多個原因時，看板只帶一個原因。**實作前與使用者確認**優先順序，確認後寫進本票的 Comments
- [ ] `list` 為每個僅監看帳號印出原因與重新納管的指令；納管帳號不印原因
- [ ] 看板模型對三種版面與 `list` 是同一份資料（版面上的顯示由 `03-watch-only-on-cards.md` 做）
