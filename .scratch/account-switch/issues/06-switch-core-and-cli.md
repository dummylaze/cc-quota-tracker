# 06: 切換本體與命令列 `switch <帳號標籤> --yes`

**What to build:** 核心新增「切換到某個帳號標籤」的入口，回傳一個結果值，區分「拒絕（沒寫任何檔）＋原因」與「成功」。命令列新增 `switch <帳號標籤> --yes`，依結果值印出訊息並回傳結束代碼。切換會寫入目標帳號的憑證快照，而且在 Claude Code 的設定檔裡只改寫帳號資訊這一個鍵。切換前後替帳號查詢額度、還原、互動確認，由後續的票做。

**Blocked by:** 02, 04

**Status:** ready-for-agent

- [ ] 以下情況拒絕，當前憑證與 Claude Code 設定檔的位元組完全不變：標籤不存在、目標是僅監看帳號（含過期）、目標就是當前憑證帳號
- [ ] 寫入前先同步當前憑證；當前憑證帳號是監看帳號而同步失敗 → 拒絕，不寫任何檔
- [ ] 寫入前保存切換前憑證（當前憑證＋當下的帳號資訊）：只有一份，每次切換都覆寫，權限收緊；它不產生卡片，也不讓任何帳號成為監看帳號
- [ ] 寫入目標的憑證快照到當前憑證；Claude Code 設定檔只改帳號資訊那一個鍵，其他鍵逐字保留，包括切換開始之後才被寫入的內容（不得用先前讀到的版本整份覆蓋）
- [ ] 以寫入時間追加一筆切換紀錄（目標帳號的帳號識別碼）；之後的 poll 偵測到同一次切換時不重複追加
- [ ] 不修改 Claude Code 的設定、不註冊 statusLine 或 hooks（ADR-0006）；不發出任何網路請求（ADR-0010）
- [ ] 不檢查刷新鎖檔；GUI 與命令列之間不加鎖，以後寫入的為準
- [ ] 命令列 `switch <帳號標籤> --yes`：成功結束代碼 0；拒絕時印出原因、結束代碼 1
- [ ] 沒帶 `--yes` → 印用法說明到 stderr、結束代碼 2，不寫任何檔（終端機裡的互動確認由 `09-cli-confirm.md` 補上）
- [ ] `--help` 的用法說明加上 `switch <帳號標籤>` 與 `--yes`

## Comments

### 尺寸（2026-10-05，切票時記）

切票時就評估本票偏大。實作時如果一個 context 裝不下，把剩下的範圍拆成新票，不在本票延伸。

### 來自 05（2026-10-06）

寫回失敗時，`ManagedDirectory.sync_snapshot` 不再丟 `OSError`，改成記進寫回失敗（`writeback_failures()`）並回傳 `None`；`None` 也可能代表「不必寫」（`05-writeback-retry.md`）。本票的「切走前先同步，同步失敗就拒絕」要用寫回失敗判斷「失敗」，不能用例外判斷。重試中或已停止重試的帳號，原因是 `WRITEBACK_RETRYING`／`WRITEBACK_STOPPED`，所以它們都是僅監看帳號，切換目標檢查會擋下它們。
