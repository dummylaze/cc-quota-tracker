# 07: 切換前後替舊帳號、新帳號查詢額度

**What to build:** 切換前先替舊帳號查一次額度，讓它變成待命帳號之後留下的讀數是新的；寫入之後立刻替新帳號查一次額度，讓新帳號的讀數馬上出現，同時確認切換真的生效。結果值多出「已寫入但驗證失敗」，以及「舊帳號查詢有沒有失敗」。命令列遇到驗證失敗時，結束代碼是 3。

**Blocked by:** 06

**Status:** resolved

- [x] 寫入前替舊帳號查詢額度；讀數沒有落後、或舊帳號沒有綁定時跳過
- [x] 舊帳號查詢失敗不影響切換，結果值會標出這件事；命令列與 GUI 都不另外提示
- [x] 寫入後替新帳號查詢額度；失敗 → 結果值是「已寫入但驗證失敗」，命令列印出訊息、結束代碼 3
- [x] 切換觸發的兩次查詢都不啟動手動查詢的冷卻：切換後可以立刻手動查詢
- [x] 切換觸發的查詢算進自動查詢的間隔（ADR-0010 修訂段）
- [x] 額度查詢仍然是請 Claude Code 代查，本工具不發出網路請求

## Comments

### 實作時定案（2026-10-06）

使用者在實作前確認：

- 舊帳號完全沒有讀數（額度快取不存在或讀不懂）時跳過查詢，與自動查詢同一條規則。
- 命令列「已寫入但驗證失敗」（結束代碼 3）印到 stderr：`已切換到「{標籤}」，但替它查詢額度失敗，沒能確認切換有生效：{原因}`，原因沿用查詢失敗的字樣；不提還原指令，因為 `switch --previous` 要到 08 才有，08 做完再補。
- 舊帳號要查的條件：有綁定的監看帳號，而且讀數「落後」或「待更新（額度快取屬於別的帳號）」；未監看帳號、沒有綁定、沒有讀數、讀數沒落後都跳過。

實作時補的（未逐條問過）：

- **舊帳號查詢之後，重讀當前憑證與設定檔、再同步一次**，才保存切換前憑證：查詢是 Claude Code 用當前憑證跑的，可能順便刷新憑證；不重做的話，切換前憑證與舊帳號的快照都會存到已作廢的 refreshToken。因此步驟順序是：檢查目標 → 同步 → 查舊帳號 → 再同步 → 保存切換前憑證 → 寫入 → 記紀錄 → 查新帳號。
- 舊帳號查詢之後，讀數立刻存成它的待命讀數，切換偵測才拿新讀數判斷「離開時落不落後」。
- 切換觸發的查詢失敗不記進看板的查詢狀態（`last_failure`、連續失敗都不動），只由結果值回報；成功才像其他查詢一樣清掉最後一次失敗、讓連續失敗歸零。
- 「已寫入但帳號資訊沒寫成」（結束代碼 3 的另一種情況）不做新帳號的驗證查詢：兩者錯配時查到的讀數沒有意義。
- 結果值的欄位：`SwitchOutcome.VERIFY_FAILED`、`old_account_query_failed`、`verify_failure`（失敗的查詢結果，命令列用它印原因）。
- 命令列 `--help` 的結束代碼 3 改成「已寫入但驗證失敗或只寫了一半」。`GLOSSARY.md` 的〈查詢額度〉補上第三種觸發。

### 交接（2026-10-06）

- **給 10、11（GUI）**：`Core.switch` 是同步呼叫，最久等兩次查詢各 20 秒，GUI 必須放背景執行。目前 `switch` 不檢查 `self._query`：看板有手動或自動查詢進行中時觸發切換，會同時開兩個 claude 子行程。GUI 票要決定是切換前等它結束、還是進行中時不給切換。結果值的 `old_account_query_failed` 在 GUI 也不另外提示（本票只提供欄位）。
- **給 08**：命令列驗證失敗的訊息要補還原指令；還原也是一次切換，同樣會查兩次，結果值沿用本票的欄位。
- **使用者故事 27「拒絕時當前憑證與帳號資訊都沒有被動過」的邊界**：舊帳號查詢之後才發生的拒絕（再同步失敗、寫不進當前憑證），Claude Code 自己可能已經改寫過額度快取（設定檔裡的 `cachedUsageUtilization`）、也可能刷新了憑證。「沒動過」指的是本工具沒有寫；這是 spec 步驟順序（查詢在保存切換前憑證之前）本來就帶的結果。
- 「兼作驗證」只確認額度快取的觀測時間前進（ADR-0010 現行定義），不核對讀數歸屬是否為新帳號。
