# 04: 憑證同步與持久的失效旗標

**What to build:** 當前憑證被 Claude Code 刷新之後，看板每輪 poll 都會把它寫回出自同一次登入的那份憑證快照（ADR-0011），所以刷新不會再讓快照作廢，也不會再讓「憑證快照已失效」亮起來。失效旗標改成只在「找不到同一次登入的證據」時才標上，例如對同一個帳號重新登入；標上之後一直保留到重新納管為止。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 當前憑證的 refreshToken 到期時間跟某份快照相差 60 秒以內、而且只有這一份符合、兩者的指紋不同 → 把當前憑證寫回這一份
- [ ] 兩份以上符合 → 不寫任何一份
- [ ] 判定只看到期時間，不看事件先後：看板沒開著時發生的刷新，下次啟動的第一輪就會補上
- [ ] 寫回走既有的原子寫入，權限跟納管時一樣收緊（用既有的 ACL 斷言輔助驗）
- [ ] 只有 GUI 的 poll 會同步；命令列的 `list`、`query`、`add`、`remove` 不會改寫任何憑證快照
- [ ] 刷新之後「憑證快照已失效」不會亮起來
- [ ] 某帳號成為當前憑證帳號時（依帳號資訊的帳號識別碼判斷），當前憑證跟它綁定的快照找不到同一次登入的證據 → 標為失效；同一個帳號識別碼綁了多份快照時，只標到期最晚的那一份
- [ ] 失效旗標持久保存，換到別的帳號也不熄滅；只有重新納管才熄滅
- [ ] 不依帳號識別碼猜測當前憑證屬於誰而改寫快照
- [ ] 指紋改變、但帳號資訊仍是同一個帳號時，不算切換，切換紀錄不追加（ADR-0009）
- [ ] 用別的工具或 `/login` 換帳號時，被換走的帳號只要在它還是當前憑證帳號時同步過，之後它的快照仍然可以用
- [ ] 工具狀態的既有檔案格式向下相容，舊檔可以直接沿用

## Comments

### 既有缺陷（2026-10-05，切票時記）

當前憑證帳號第一次被刷新之後，「憑證快照已失效」就會一直亮著（已實際應驗）。本票的憑證同步會修掉這個問題。待命帳號的快照作廢後，到期倒數仍顯示有效，這個問題也由本票根治（另見 `02-account-info-and-switchable.md`）。**修之前先對出問題的行跑 `git blame`，找出引入它的 commit。**
