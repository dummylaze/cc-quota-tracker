# 05: 寫回失敗重試與卡片提示

**What to build:** 憑證同步寫回快照失敗時，該帳號暫時是僅監看帳號，卡片顯示「寫回快照失敗，自動重試 n/3」。之後每輪 poll 重試一次：成功就自動恢復成納管帳號；3 次都失敗就停止重試，改成提示重新納管。下一次 Claude Code 又刷新（當前憑證的指紋改變）時，重試次數重新計算。

**Blocked by:** 03, 04

**Status:** resolved

- [x] 寫回失敗 → 該帳號是僅監看帳號，原因是「寫回失敗（重試中 n/3）」，卡片顯示「寫回快照失敗，自動重試 n/3」（中英文語系）
- [x] 每輪 poll 最多重試一次；重試成功 → 恢復成納管帳號，不需要使用者做任何事
- [x] 3 次都失敗 → 停止重試，原因改成「寫回失敗（已停止重試）」，卡片提示重新納管
- [x] 重試次數在重新啟動之後仍然記得；當前憑證的指紋改變時重新計算
- [x] `list` 的原因同樣反映重試中與已停止重試
- [x] 寫回失敗不影響看板的其他部分，也不跳對話框

## Comments

### 來自 03（2026-10-06）

僅監看帳號在卡片上統一是一條「僅監看帳號（{原因}）：在 Claude Code 登入這個帳號後重新納管」（`note.watch_only`），原因字樣由 `fmt.watch_only_reason` 對照 `watch_only.reason.*`；色點在 `canvas_text.notes()` 依原因分支，目前只有「沒有帳號資訊」用 sub，其他都是 critical（`03-watch-only-on-cards.md`）。本票新增寫回失敗的兩種原因時要決定：卡片的「寫回快照失敗，自動重試 n/3」是取代這一條的字樣、還是只當原因套進去；重試中（自動會好、不需使用者動手）的補救句也不適用「重新納管」。

### 實作前與使用者確認（2026-10-06）

- 次數：n 是已失敗的次數，總共寫 3 次。第 1 次失敗顯示 1/3，第 3 次失敗就停止重試。
- 卡片字樣：重試中整條取代僅監看帳號那一條，改成「寫回快照失敗，自動重試 n/3」，不帶重新納管（會自己好），用 warning 色。停止後套用原因：「僅監看帳號（寫回快照失敗，已停止重試）：在 Claude Code 登入這個帳號後重新納管」，用 critical 色。
- 原因的優先順序：已過期 > 已失效 > 寫回失敗（重試中／已停止重試）> 沒有帳號資訊。
- 寫回失敗期間換到別的帳號（當前憑證已經不是那次登入，沒有東西可以重試）：直接改成「已停止重試」。之後又換回同一次登入時，重新計數再試。

### 實作中與使用者確認（2026-10-06）

- `list`：重試中的帳號只印原因、不印重新納管的指令（跟卡片一致，重試中會自己好）。spec〈`list`〉「為每個僅監看帳號列出原因與重新納管的指令」的例外。
- 綁定檔讀不到而寫不成，也算一次寫回失敗。

### 結案說明（2026-10-06）

- 寫回失敗存在納管目錄的 `.state/writeback.json`：以沒寫成的憑證快照的憑證指紋為鍵，記當時當前憑證的憑證指紋、失敗次數、是否已停止重試。可以同時有好幾筆（例如兩個帳號先後寫回失敗）。寫回成功、重新納管、移除時會清掉（那份憑證指紋已經不在了）。
- `ManagedDirectory.sync_snapshot` 寫回失敗時不再丟 `OSError`，改成記進寫回失敗、回傳 `None`。`ManagedDirectory.writeback_failures()` 給核心與命令列讀。命令列不會寫回，但 `list` 讀得到看板記下的狀態。
- `writeback.json` 讀不到時照樣寫回，但失敗不記次數。寫不成也不丟例外，下一輪再記。
- 卡片新增 `writeback_failures`（重試中已經失敗幾次）。`WatchOnlyReason` 新增 `WRITEBACK_RETRYING`、`WRITEBACK_STOPPED`，宣告順序就是優先順序。
- `tests/test_watch_only_cards.py` 原本「每種原因都套用重新納管那一條」的 4 個迴圈，改成只跑原來的三種原因；寫回失敗的兩種原因另外寫在 `tests/test_writeback_retry.py`。
