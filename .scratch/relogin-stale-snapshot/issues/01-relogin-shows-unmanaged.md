# 01: 重新登入已納管的帳號後，看板顯示「未納管帳號」，同帳號的待命卡同時存在

**What to build:** 先登入別的帳號、再重新登入一個已納管的帳號（refreshToken 換了新的），看板的使用中卡片變成「未納管帳號」，下面又有同一帳號的待命卡，讀數相同，卡片上沒有任何提示。判定要改成：當前憑證指紋對不上任何憑證快照、但 `oauthAccount` 的帳號識別碼已綁給某份憑證快照時，使用中帳號就是那份憑證快照的帳號，並標記憑證快照已失效（詞條見 `CONTEXT.md` 的「失效的憑證快照」）。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 重現情境：納管 A、B，登入 A，再以新 refreshToken 登入 B → 使用中卡是 B 且帶「憑證快照已失效」，沒有未納管卡，B 沒有重複的待命卡；`list` 輸出同樣顯示失效與重新納管的指令
- [x] 這一次登入寫一行切換紀錄，記 B 綁定的識別碼；之後的輪次不重複寫
- [x] 同一帳號被輪替（前一個使用中的就是它）仍不算切換，不寫紀錄
- [x] 空窗：憑證先寫、`oauthAccount` 還是舊的那一輪，行為與現在相同（當作前一個帳號被輪替、不寫紀錄）；`oauthAccount` 跟上的下一輪改判為切換，旗標移到新帳號
- [x] 同一識別碼綁了多份憑證快照：只標到期最晚的那份，另一份維持待命且不標；失效卡與 `list` 的重新納管指令寫的是被標的那份的標籤
- [x] 識別碼讀不到時不新增旗標；識別碼沒綁給任何憑證快照時仍是未納管帳號
- [x] 重新納管（`add` 同一標籤）後旗標熄滅、不寫切換紀錄；憑證快照檔與 Claude Code 的檔案全程不被寫入
- [x] `observed.json`、`switches.jsonl` 格式不變，舊檔可直接沿用
- [x] README 與 README.zh-TW 在說明「憑證快照已失效」的段落補一句：重新登入已納管的帳號後，看板也會顯示失效，重新納管即恢復；兩版同一次編輯一起改

## Comments

### 來源（2026-10-03）

使用者實機回報。查證只比對憑證指紋前綴與到期時間，沒有讀 token：當前憑證與四份憑證快照的指紋都不相符，到期時間比該帳號的憑證快照晚，確認是重新登入換了新 refreshToken。

### Triage（2026-10-03）

> *This was generated by AI during triage.*

**類別**：bug。違反 M1 spec 故事 29（憑證快照失效要在卡片上看到「請重新納管」）：M1 票 07 只涵蓋「前一個使用中的就是這個帳號」這一條路，「前一個是別人」沒人涵蓋。

**重現（實測，拋棄式測試，未進 repo）**：納管 A、B → 登入 A → 以新 refreshToken 登入 B。使用中卡 `UNMANAGED`、A 與 B 都是待命、`list` 沒有任何提示；切換紀錄為 `[B, A, B]`，最後一筆已是 B 的識別碼。

**根因**：判定「輪替」要求前一個使用中帳號的識別碼等於 `oauthAccount`；前一個使用中是 A，於是落入「切到未納管帳號」。判定看的是「前一個是誰」，不是「現在這個識別碼綁給誰」。

**已定案**（出處：使用者回覆 Q1～Q4；事實部分為實測）：

- 呈現：沿用既有的失效卡，不新增卡片狀態與字樣。判定不看前一個使用中帳號。
- 空窗不加防護：不等識別碼穩定、不核對額度快取的識別碼（額度快取的識別碼比 `oauthAccount` 更慢，ADR-0002 寫可能落後數小時）。空窗誤判一輪，下一輪自己改回；這個判定只是提示，不改任何檔案。
- 切換紀錄不處理：紀錄存識別碼（ADR-0009），重現中最後一筆已是 B；「未納管」只是畫面上的角色，沒有寫進紀錄。紀錄只追加，不補寫。
- 同一識別碼多份憑證快照：只標到期最晚的那份（使用者決定）。到期相同或都沒有到期時間時，取帳號標籤排序在前的。這是實測發現的前提：目前 `add` 不擋、也不警告同一帳號以兩個標籤納管。
- 詞彙：已更新 `CONTEXT.md`（收斂「未納管帳號」，新增「失效的憑證快照」）。不開 ADR。

**給第二版（工具內切換帳號）的前置事項**：本票不處理，列出來讓第二版的 grill 看得到。

1. 失效判定只能當提示，不能當寫回憑證快照的條件。空窗那一輪會誤判，ADR-0002 禁止自動改寫的理由正是誤判會用別的帳號的憑證蓋掉快照。第二版寫回需要更強的證據（連續幾輪穩定、或使用者按鈕確認）。
2. 失效旗標只對使用中帳號成立，離開就清掉（既有行為，有測試守著），這一票也不改。結果是待命卡看不出該快照已經過期，只有到期倒數。第二版若讓使用者點待命卡切換，可能把一份已死的憑證寫進 Claude Code。重新登入後舊 refreshToken 是否真的失效尚未實測（推測）。
3. 同一識別碼多份憑證快照時「取到期最晚」可以當第二版選切換目標的預設規則；未標的那份是否仍該被允許切換，到時再議。

### Agent Brief（2026-10-03）

**Category:** bug
**Summary:** 憑證指紋對不上任何憑證快照、但帳號識別碼已綁給某份憑證快照時，使用中帳號是那份憑證快照的帳號並標記憑證快照已失效，不再顯示成未納管帳號。

**Current behavior:**
每輪的切換偵測在憑證指紋改變且對不上任何憑證快照時，只在「前一個使用中的納管帳號的識別碼等於 `oauthAccount` 的識別碼」才判為輪替（旗標、不算切換）。前一個使用中的是別的帳號時，判為切到未納管帳號：看板的使用中卡片是未納管帳號，同一帳號的待命卡同時存在，沒有提示。

**Desired behavior:**
- 每輪：當前憑證讀得到、指紋對不上任何憑證快照，且 `oauthAccount` 的識別碼讀得到並已綁給至少一份憑證快照時，使用中帳號是那個識別碼的帳號，並帶「憑證快照已失效」（`snapshot_invalid`）。判定不看前一個使用中帳號。
- 綁了多份憑證快照時，被標的是到期最晚的那份；到期相同或都沒有到期時間，取帳號標籤排序在前的。其餘維持待命、不標、卡片內容不變。失效卡與 `list` 的重新納管指令用被標的那份的標籤。
- 切換紀錄：憑證指紋改變時，若新判定的帳號（識別碼）與前一個使用中的納管帳號相同，是輪替，不寫紀錄；否則是切換，寫一行該識別碼，離開帳號的落後標記照現有切換的做法處理。已標失效後的後續輪次不重複寫。
- 空窗：Claude Code 先寫憑證、後寫 `oauthAccount`。`oauthAccount` 還是前一個帳號的那一輪，結果與現在相同；跟上之後的下一輪改判為切換，旗標移到新帳號，舊帳號不再標。
- 識別碼讀不到：不新增旗標，沿用上一輪存下的旗標（現有行為）。識別碼沒綁給任何憑證快照：仍是未納管帳號。
- 重新納管（`add` 同一標籤）後旗標熄滅，不寫切換紀錄。
- 不寫入憑證快照檔、Claude Code 的任何檔案；`observed.json`、`switches.jsonl` 的格式不變。

**Key interfaces:**
- 切換偵測（`Core` 內每輪的觀測）：失效帳號的來源由「前一個使用中帳號」擴大為「`oauthAccount` 識別碼綁定的憑證快照」。
