# 納管目錄 module

Status: resolved

## 問題陳述（Problem Statement）

本工具保管的資料都放在納管目錄：憑證快照、綁定、待命帳號的最後讀數、上一輪的觀測、切換紀錄、視窗位置。其中綁定與切換紀錄一旦弄丟就補不回來：綁定要等該帳號再次成為使用中帳號才會被補學，切換紀錄則事後無法補寫（ADR-0003、ADR-0009）。

這些資料的讀寫規則目前散在核心的十幾個方法和視窗程式裡。最重要的一條規則是：「暫時讀不到（例如被防毒鎖住）」不等於「不存在」，讀不到時不得把整份資料當成空的寫回去。這條規則只寫在某些呼叫端：每輪 poll 有守，納管與移除沒有守（票 01）。同樣的「不存在／讀不到／讀不懂」三態讀取寫了三份；收緊權限有兩套政策，視窗程式的那一套不驗證；測試只能透過全域替換檔案讀取函式，從核心的外部間接模擬鎖檔。

結果是：維護者每加一個會寫納管目錄的入口，都要自己記得這些規則；漏記不會報錯，只會在某天檔案被鎖住時，靜默地洗掉使用者的資料。接下來的功能（statusLine 資料源、從工具內切換帳號、逐帳號 token 報表）都會再增加讀寫納管目錄的入口。

## 解決方案（Solution）

把納管目錄的所有讀寫集中到一個「納管目錄」module，對外只提供領域操作，例如納管一份憑證快照、移除、補學綁定與清孤兒、記住待命讀數、記錄這一輪的觀測與切換、讀寫視窗位置。三態讀取、「讀不到就拒絕修剪性寫入」、原子寫入、權限收緊與事後驗證，都在 module 內部強制執行，呼叫端不必、也無法繞過。

核心與視窗都只透過這個 module 存取納管目錄。這是一次零行為變更的重構：使用者看到的畫面、命令列輸出與納管目錄裡的檔案格式都不變。唯一的例外是視窗位置改用與其他工具狀態相同的權限政策（見〈實作決策〉）。

## 使用者故事（User Stories）

### 使用者：資料安全

1. 身為使用者，我想在防毒或備份軟體短暫鎖住納管目錄裡的檔案時，帳號綁定不會消失，這樣待命帳號的讀數仍然歸屬得到。
2. 身為使用者，我想在任何一個入口（每輪 poll、命令列納管、GUI 納管、匯入憑證檔、移除）遇到檔案被鎖住時，都得到相同的保護，才不必知道是從哪裡操作的。
3. 身為使用者，我想讓待命帳號的最後讀數，不會因為某一次讀不到綁定檔就被修剪掉。
4. 身為使用者，我想讓切換紀錄在任何情況下都只追加、不被改寫，才能在日後把用量歸屬到正確的帳號。
5. 身為使用者，我想讓納管目錄與其中每一個檔案，不論是哪個入口建立的，都只有我自己能存取。
6. 身為使用者，重構前後我想看到完全相同的畫面、命令列輸出與錯誤訊息，才能確定升級不會改變我已經熟悉的行為。
7. 身為使用者，我想讓重構前寫下的納管目錄（憑證快照、綁定、讀數、觀測、切換紀錄、視窗位置）在重構後照樣讀得懂，不需要任何遷移。
8. 身為使用者，我想讓視窗位置跟其他工具狀態一樣只有我自己能存取。
9. 身為使用者，如果納管目錄所在的位置收不緊權限，我想讓視窗位置的行為與其他工具狀態一致，而不是例外地照樣寫入。

### 維護者：新增入口與修改規則

10. 身為維護者，我想用一個領域操作完成「納管一份憑證快照」，不必自己依序處理建立目錄、驗證憑證、收緊權限、寫入綁定與修剪讀數。
11. 身為維護者，我想在新增一個會寫納管目錄的功能（例如 statusLine 資料源、切換帳號後寫回憑證快照）時，不必重新實作「讀不到就不寫回」的保護。
12. 身為維護者，我想讓三態讀取只有一份實作，修正一次就涵蓋所有種類的工具狀態。
13. 身為維護者，我想讓權限政策只有一套，不必判斷某個檔案該用哪一套。
14. 身為維護者，我想讓核心只負責每輪 poll 的編排、額度快取的讀取、帳號身分的判定與看板組裝，不再處理納管目錄的檔案細節。
15. 身為維護者，我想讓視窗程式不再知道工具狀態子目錄的名稱與位置，也不再依賴「核心已經先建好並收緊這個目錄」的呼叫順序。
16. 身為維護者，我想讓帳號標籤的合法性檢查（不能用作檔名的字元、Windows 保留名稱）與憑證快照的檔名規則放在同一處，因為標籤就是憑證快照的檔名。
17. 身為維護者，我想在 AI 協作時，只讀一個 module 就能知道納管目錄有哪些檔案、各自的寫入規則與失敗處理。

### 維護者：測試

18. 身為維護者，我想直接對納管目錄 module 注入故障（讀取時被鎖住、內容讀不懂、寫入失敗、某份憑證快照讀不出憑證指紋），而不必透過核心的完整 poll 間接製造情境。
19. 身為維護者，我想讓既有的縫 ① 測試在重構期間一行都不必改、全部維持通過，作為零行為變更的證據。
20. 身為維護者，我想讓切換紀錄的檔案格式（ADR-0009 的契約）繼續由讀檔的黑箱斷言守住，不因為改走 module 的讀取而失去對格式本身的檢查。
21. 身為維護者，我想讓票 01 新增的「讀不到不洗掉綁定」測試在重構後照樣通過，證明保護沒有在搬移時遺失。

## 實作決策（Implementation Decisions）

- **新 module：納管目錄（Managed Directory）**，沿用 `CONTEXT.md` 既有詞條的英文名稱命名，不新增詞條。它擁有整個納管目錄：憑證快照、綁定、待命讀數、上一輪觀測、切換紀錄、視窗位置。
- **interface 以領域操作為單位，不以檔案為單位**。至少涵蓋：
  - 列出納管帳號：每個帳號標籤對應的憑證指紋（讀不出來時為「未知」）、憑證快照到期時間、綁定的帳號識別碼。
  - 納管一份憑證快照（帳號標籤、憑證內容、帳號識別碼或無）：檢查帳號標籤的合法性、替換前驗證憑證讀得出憑證指紋、收緊權限並事後驗證，回報是否修正過既有權限、是否未綁定。帳號標籤像 email 的提示仍由現有的回報方式帶出。
  - 移除一個帳號標籤的憑證快照。
  - 綁定維護：補學一筆綁定、清除孤兒綁定，並連帶修剪待命讀數。
  - 待命讀數：讀出全部、記住一筆。
  - 上一輪觀測：讀出（區分「沒有」與「讀不到」）、寫入。
  - 切換紀錄：追加一筆。
  - 視窗位置：讀出、寫入。
- **module 內部強制執行的規則**：
  - 三態讀取：不存在與讀不懂視為空的，讀不到（作業系統層的讀取錯誤）視為「未知」。
  - 會修剪資料的寫入（綁定、連帶的待命讀數）：只要綁定檔讀不到、或有任何一份憑證快照讀不出憑證指紋，就不修剪。這個 module 對外的行為，以票 01 實作後的行為為準（納管與匯入在綁定檔讀不到時整個拒絕；移除時不寫綁定檔；有快照讀不出來時只加入新綁定）。
  - 一律原子寫入；暫存檔在替換前就收緊權限；目錄先收緊再往裡面寫。
  - 切換紀錄只追加。
  - 待命讀數在記憶體中的快取由 module 擁有。
- **權限政策統一**：視窗位置改用與其他工具狀態相同、會事後驗證的收緊方式。收不緊時，視窗位置的寫入照樣失敗，視為「這次沒記住」，行為與其他工具狀態一致。這是本次重構唯一的行為差異，只影響收不緊權限的檔案系統（例如 exFAT）。
- **核心保留**：每輪 poll 的編排、額度快取讀取與「一輪」語意、設定檔重讀、帳號身分與切換的判定、看板組裝。核心原本直接讀寫檔案的部分，改為呼叫 module 的領域操作；判定的邏輯本身不在這次搬移。
- **視窗程式**：只透過 module 讀寫視窗位置，不再引用工具狀態子目錄的名稱，也不再直接呼叫權限函式。
- **納管目錄內的檔案路徑與格式不變**，不需要遷移。
- **已知限制（寫進 module 的說明）**：GUI 與命令列是兩個程序，同時寫綁定檔時沒有跨程序的鎖；兩者在同一輪內交錯時，後寫的會蓋掉先寫的。發生機率低，被蓋掉的綁定若屬於使用中帳號，之後的 poll 會補學回來。

## 測試決策（Testing Decisions）

- **好的測試只看外部行為**，透過兩道縫觀察：
  - **縫 ①（照舊）**：核心的 poll／add／remove／import 回傳的看板，以及它寫進納管目錄的檔案。既有的縫 ① 測試全部不修改、全部通過，作為零行為變更的證據。
  - **縫 ④（新增）**：納管目錄 module 的 interface。用暫存目錄建立真實的納管目錄，主要用來做故障注入：讀取時被鎖住、內容讀不懂、寫入失敗、某份憑證快照讀不出憑證指紋。斷言只看 module 的回傳值與目錄裡檔案的內容，不看 module 內部的方法。
- 不直接測 module 的內部函式；縫 ① 仍是主要的測試面，縫 ④ 補上縫 ① 很難製造的故障情境。
- 既有用全域替換檔案讀取函式模擬鎖檔的測試保留；只有在與縫 ④ 的新測試完全重複時才刪除。
- 切換紀錄的讀檔斷言保留：那是 ADR-0009 的檔案格式契約，不改走 module 的讀取。
- 權限：沿用既有在 Windows 真實暫存目錄上驗證權限確實收緊的斷言寫法；視窗位置新增一條同樣的斷言。
- **先例**：綁定維護的鎖檔測試（替換檔案讀取函式，對指定檔名丟出權限錯誤）、納管帳號的權限驗證測試、待命讀數的權限測試、憑證儲存的測試。
- 測試框架維持標準庫的 `unittest`。

## 範圍外（Out of Scope）

- 任何使用者看得到的行為變更（視窗位置的權限政策除外）。納管與移除在讀不到檔案時的新行為屬於票 01，本 spec 以它為前提。
- 收不緊權限的檔案系統上的整體行為（票 02）。
- 把帳號身分與切換的判定抽成獨立的 module、把額度快取讀取抽成獨立的 module：等從工具內切換帳號開工時再評估。
- 卡片呈現、Canvas 物件生命週期、偏好的集中：另行評估。
- 跨程序的檔案鎖。
- 從工具內切換帳號所需的寫回憑證、切換紀錄的新來源。
- statusLine 資料源（另一個 feature）。
- 改變納管目錄內任何檔案的路徑或格式。

## 補充說明（Further Notes）

- 起因：架構審查發現納管目錄的讀寫規則分散，其中「讀不到不寫回」的保護只做在 poll 路徑，納管與移除沒有（票 01）。
- 依賴：本 spec 的票都排在票 01 之後；票 01 新增的測試是這次重構的安全網。
