# 05: 列出納管帳號與 poll 的綁定維護搬進納管目錄 module

**What to build:** 每輪 poll 要用的「列出納管帳號」（每個帳號標籤的憑證指紋或「未知」、憑證快照到期時間、綁定的帳號識別碼）、「補學一筆綁定」、「清除孤兒綁定並連帶修剪待命讀數」改由納管目錄 module 提供。「綁定檔讀不到、或有任何一份憑證快照讀不出憑證指紋，就不修剪」這條規則改在 module 內部強制執行，呼叫端無法繞過。核心保留「補學哪一份」的判定，不在這次搬移。

**Blocked by:** `04-standby-readings.md`

**Status:** resolved

- [x] 核心不再直接讀寫綁定檔，也不再自己過濾憑證指紋或修剪待命讀數
- [x] 縫 ④ 測試：綁定檔被鎖住時，補學與清孤兒都不寫檔，綁定檔與讀數檔位元組不變
- [x] 縫 ④ 測試：某份憑證快照讀不出憑證指紋時，列出的帳號該份為「未知」，且不修剪任何綁定與待命讀數
- [x] 縫 ④ 測試：綁定檔寫入失敗時丟出例外，綁定檔維持原樣
- [x] 縫 ④ 測試：清孤兒綁定時，連帶刪掉已無綁定的帳號的待命讀數
- [x] 既有以替換檔案讀取函式模擬鎖檔的測試保留；只有與縫 ④ 新測試完全重複時才刪除，刪了哪些寫進本票 Comments
- [x] 綁定檔的三態讀取改用 module 內的 `_read_state`，核心的 `_load_bindings` 刪除
- [x] 核心的 `_write_state` 轉手與 `STATE_DIR`、綁定檔與讀數檔的路徑組合刪除，`ManagedDirectory.write_state` 改為 module 內部（票 03 為了給核心尚未搬的綁定、讀數使用而暫時公開）
- [x] 既有縫 ① 測試一行未改、全部通過


## Comments

### 票 03 留下的過渡項（2026-10-02）

票 03 為了讓核心尚未搬的部分繼續運作，暫時公開了 `STATE_DIR`、`ManagedDirectory.write_state`，核心的 `_write_state` 只是一行轉手。票 04 搬走讀數、本票搬走綁定之後，核心不再有呼叫處，這兩個收回 module 內部。

### 票 04 留下的過渡項（2026-10-02）

票 04 搬走待命讀數時，為了讓核心尚未搬的 `_write_bindings` 繼續運作，module 暫時公開了 `prune_standby_readings(bound)`。本票把「清孤兒綁定並連帶修剪待命讀數」搬進 module 之後，核心不再有呼叫處，這個方法併入綁定維護、收回 module 內部。這是既有驗收項「核心不再修剪待命讀數」的落地方式，不改變本票範圍。

### 實作時的決定（2026-10-02）

- 補學一筆與清孤兒合成一個操作 `maintain_bindings(learn)`，一次寫完，沒有要補也沒有要清就不寫；回傳有沒有寫，核心據此決定要不要重列帳號。「補學哪一份」的判定（`_snapshot_to_bind`）留在核心，只加了「當前憑證讀不出憑證指紋就不補」，原本由「全部憑證指紋都讀得出來」的前置檢查擋著，現在檢查搬進 module，這句要自己補上。
- `prune_standby_readings` 收回 module 內部（`_prune_standby_readings`），由綁定的寫入呼叫。原本針對它的縫 ④ 測試改成經 `maintain_bindings`／`prune_bindings` 驗證同樣的行為（孤兒連帶刪讀數、讀數檔鎖住不修剪、沒有要清的不寫讀數檔）；沒有刪任何縫 ① 測試，既有的鎖檔測試都保留。
- 納管與移除（票 06 才搬）還需要讀寫綁定，過渡期 module 暫時公開 `snapshot_labels`、`check_bindings_readable`、`record_binding`、`prune_bindings`，票 06 把納管、移除搬進來時併入、收回內部。`BindingsUnreadable` 搬進 module（核心照舊匯出，命令列、GUI、既有測試的匯入路徑不變）。
- 唯一的細微差異：納管時綁定檔的讀取由一次變兩次（寫憑證快照前確認讀得到、記綁定時再讀一次）。兩次之間綁定檔才被鎖住的話，原本會拿舊內容蓋回去，現在丟 `BindingsUnreadable`，憑證快照已寫入、綁定維持原樣。
