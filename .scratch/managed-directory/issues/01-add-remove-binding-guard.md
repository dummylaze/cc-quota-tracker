## Agent Brief

**Category:** bug
**Summary:** 納管、匯入、移除在綁定檔或其他憑證快照讀不到時，會把其他帳號的綁定與待命讀數靜默清掉

**Current behavior:**
`Core.add`、`Core.import_snapshot`、`Core.remove` 讀綁定檔時，把「讀不到」（暫時被鎖住）與「不存在／讀不懂」一律當成空的綁定，再整份寫回，其他帳號的綁定因此消失。寫回綁定時又只保留「目前讀得出憑證指紋的憑證快照」對應的綁定，並依此修剪待命帳號的最後讀數；任何一份憑證快照剛好讀不到，它的綁定與讀數就一起被清掉。每輪 poll 的綁定維護已區分這兩種情況，遇到讀不到就整輪不動，但納管與移除沒有走這個保護。

**Desired behavior:**
- 納管與匯入：寫入憑證快照**之前**先確認綁定檔讀得到（「不存在」與「讀不懂」照舊視為空的綁定，可以寫）。讀不到就丟出一個新的例外（與 `NoCredential`、`InvalidLabel` 同層級），不動任何檔案。命令列 `add` 印出錯誤到 stderr 並以非零狀態結束（與 `NoCredential` 相同）；GUI 的「納管目前登入的帳號」與「匯入憑證檔」都以錯誤對話框呈現。
- 移除：憑證快照照常刪除；綁定檔讀不到時不寫綁定檔、不丟錯誤，使用者看到的是移除成功。
- 納管、匯入、移除寫回綁定時，若有任何一份憑證快照讀不出憑證指紋，這一次不修剪既有綁定，也不修剪待命讀數；只加入（納管時）這次的新綁定。之後的 poll 會在所有快照都讀得到時清掉孤兒綁定。
- 新文案語意（實作前與使用者確認措辭）：綁定檔暫時讀不到、可能被其他程式鎖住，憑證快照沒有變更，請稍後再試一次。命令列與 GUI 可共用同一個文案鍵；兩個語系都要有。

**Key interfaces:**
- `Core.add(label)`、`Core.import_snapshot(source, label)`：讀不到綁定檔時丟新例外，且在寫入憑證快照之前就丟
- `Core.remove(label)`：讀不到綁定檔時不寫綁定檔，不丟例外
- 寫回綁定並修剪待命讀數的那段共用邏輯：要能分辨「快照讀不出憑證指紋」並在那時跳過修剪
- 命令列入口與 GUI 的納管／匯入處理：捕捉新例外並顯示新文案
- 語系檔：新增一個錯誤文案鍵（正體中文、英文）

**Acceptance criteria:**
- [ ] 綁定檔讀不到時 `add` 丟出新例外；憑證快照目錄、綁定檔、待命讀數檔的位元組都與之前相同
- [ ] 綁定檔讀不到時 `import_snapshot` 行為同上，且覆寫既有標籤的情況下，舊的憑證快照保持原樣
- [ ] 命令列 `add` 遇到這個例外時，印出新文案到 stderr，結束碼為 1
- [ ] GUI 的納管與匯入遇到這個例外時，跳出錯誤對話框顯示新文案
- [ ] 綁定檔讀不到時 `remove` 照常刪除憑證快照，不丟例外，綁定檔位元組不變；綁定檔恢復可讀後的下一次 poll 清掉孤兒綁定
- [ ] 有其他憑證快照讀不出憑證指紋時，`add`／`import_snapshot`／`remove` 都不刪除那份快照的綁定，也不刪除它的待命讀數
- [ ] 以上情境都有縫 ① 的測試（沿用以 patch 模擬鎖檔的寫法）；全部既有測試通過

**Out of scope:**
- 每輪 poll 的綁定維護（已有保護）
- 把納管目錄的讀寫收成一個 module（同一 feature 之後的重構票，會以本票的測試當安全網）
- 跨程序（GUI 與命令列同時寫綁定檔）的並行寫入
- 納管目錄所在檔案系統收不緊權限時的行為（另開票）
- 寫入失敗（讀得到但寫不進去）的重試
