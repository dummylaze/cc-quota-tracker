# 07: 視窗位置改走納管目錄 module，權限政策統一

**What to build:** 視窗程式只透過納管目錄 module 讀寫視窗位置，不再知道工具狀態子目錄的名稱，也不再直接呼叫權限函式。視窗位置改用與其他工具狀態相同、會事後驗證的收緊方式：收不緊權限時（例如 exFAT），這次的位置寫入失敗，視為「這次沒記住」，與其他工具狀態一致。這是本 feature 唯一的使用者可見差異，只影響收不緊權限的檔案系統。

**Blocked by:** `03-observed-and-switch-log.md`

**Status:** resolved

- [x] 視窗程式不再引用工具狀態子目錄的名稱，也不再匯入權限函式
- [x] 工具狀態目錄還不存在時（還沒成功 poll 過），維持現行行為：不記住位置
- [x] 收緊後事後驗證不符時，這次不記住位置，下一次移動或結束時再試；視窗照常運作
- [x] 重構前寫下的視窗位置檔照樣讀得懂；讀不懂或讀不到時照舊回到預設位置
- [x] 新增視窗位置檔的 Windows 實際權限斷言（沿用其他工具狀態的寫法）
- [x] 視窗位置的讀取改用 module 內的 `_read_state`，視窗程式自己那份讀檔與三態判斷刪除；`from .core import STATE_DIR` 也一併移除
- [x] 既有縫 ① 與視窗測試一行未改、全部通過

## Comments

### 票 03 留下的過渡項（2026-10-02）

票 03 起 module 內的 `_read_state` 是三態讀取的唯一一份；視窗程式的位置讀取是最後一份副本，本票刪除。視窗位置原本「讀不懂或讀不到都回到預設位置」，兩種落在同一個結果，改用 `_read_state` 時照舊，不需要區分「未知」。

### 結案說明（2026-10-02）

- 視窗位置的讀寫是 module 的 `read_window_position`／`write_window_position`。寫入回傳「這次有沒有記住」：工具狀態目錄還不存在、寫不成、收不緊權限都回傳 False，不建目錄也不丟例外，視窗程式不更新已記住的位置，下次移動或結束時再試。
- 視窗位置檔改由 module 寫，內容多了縮排（與其他工具狀態一致）；欄位不變，舊檔（緊湊格式）照樣讀得懂，有測試。

### 收不緊時的行為由票 08 改變（2026-10-03）

本票「收不緊權限時這次不記住位置」的行為，由 `08-untightened-warning.md` 改為照常寫入，與其他工具狀態一致（ADR-0008）。本票範圍不變。
