## Triage Notes

**What we've established so far:**

- ADR-0008 的後果寫：納管目錄搬到不支援 ACL 的檔案系統時，「權限收緊不會生效，只會持續發出告警」。
- 程式碼沒有這條告警路徑。收緊權限的共用函式收不緊時丟 `PermissionError`（給開發者的診斷），呼叫端沒有任何一處把它轉成告警；`add` 的「權限已修正」警告只涵蓋「收得緊」的情況。
- 以縫 ① 模擬（把「是否已收緊」固定回傳否，「收緊」分別模擬成「成功但沒效果」與「回報不支援」）：
  - 還沒納管任何帳號時，poll 成功。
  - `add` 一律失敗：分別丟 `PermissionError` 與 `OSError`（不支援）。命令列沒有捕捉這兩種例外，會印出 traceback。
  - 先在正常位置納管、再模擬搬到這類位置：額度快取的讀數有變化時，記住待命讀數的寫入丟出 `PermissionError`，**整輪 poll 失敗**；讀數沒變化的輪次 poll 成功。
  - 每輪記錄最後運作時間與切換紀錄的寫入失敗會被吞掉（「下一輪重試」的設計），所以這類位置上**切換紀錄與最後運作時間會靜默地不再寫入**，而這兩份紀錄事後無法補寫（ADR-0003）。
- GUI 每輪 refresh 只有 `try/finally`、沒有 `except`：poll 失敗時例外跑出 Tk 的回呼，以 `pythonw` 啟動時看不到；排程照樣排下一輪，所以看板會停在最後一次成功的畫面，不顯示任何橫幅（讀碼確認，未在 GUI 實跑）。
- 尚未確認的是**真實的 exFAT／FAT32 上，系統呼叫實際回傳什麼**：查詢權限可能直接回報錯誤（又一種失敗路徑）、回傳空的 DACL，或寫入權限時回報不支援／假裝成功。上面的模擬涵蓋後兩種，第一種還沒模擬。
