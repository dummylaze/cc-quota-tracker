# 查詢額度

Status: ready-for-agent

## 問題陳述（Problem Statement）

本工具的用量讀數全部來自額度快取，而額度快取只在 Claude Code 執行 `/usage`、登入等時機才會更新。持續對話時，使用中帳號的讀數會系統性落後，一小時以上很常見。工具雖然會標出落後讀數，但使用者每次都得切到 Claude Code、手動執行 `/usage`，數字才會變新。

使用者主要在 VS Code 的 Claude Code 面板裡對話。面板每輪都顯示最新的額度，但那份數字只存在擴充套件的記憶體裡，本工具讀不到；面板也不會執行 `statusLine`，所以 statusLine 接不到資料。

切換帳號時還有一個漏洞：讀數只對使用中帳號判斷落後。使用者在工具外切到另一個帳號後，舊帳號那份已經落後的讀數會變成待命讀數，畫面上看起來跟準確的讀數一模一樣。

## 解決方案（Solution）

本工具可以「查詢額度」：請 Claude Code 去查使用中帳號的最新額度，由 Claude Code 寫回額度快取，工具再照原本的流程讀進來（ADR-0010）。工具自己不發網路請求、不碰 token，也不讀查詢的回應。

- **手動**：使用中帳號的卡片在落後或讀數待更新時，提示旁邊有一個「更新」入口；右鍵選單和命令列也可以查詢。
- **自動（選用，預設關閉）**：開啟後，只在使用中帳號的讀數落後或讀數待更新時查詢，兩次查詢之間至少隔一段使用者設定的間隔，間隔有不可再低的下限。人離開電腦、沒有新的對話活動時，讀數不再落後，自動查詢自然停止。
- **切換前已落後**：切換時已經落後的讀數，舊帳號成為待命帳號後仍然標為落後，直到出現屬於它的新讀數。

## 使用者故事（User Stories）

### 使用者：手動查詢

1. 身為使用者，看到使用中帳號的讀數落後時，我想在卡片上直接按一下就查詢額度，不必切到 Claude Code 打 `/usage`。
2. 身為使用者，在讀數待更新（剛切換、還沒有屬於新帳號的讀數）時，我想用同一個入口查詢，讓新帳號的讀數立刻出現。
3. 身為使用者，我想在三種版面上都找得到這個入口，不因為換了版面就沒有。
4. 身為使用者，我想在右鍵選單也能查詢額度，在讀數沒有標為落後時（例如我剛在別的裝置用過）也能主動查詢。
5. 身為使用者，按下之後我想看到「查詢中」的狀態，入口暫時不能再按，才知道工具正在處理、不會重複送出。
6. 身為使用者，查詢成功時我想看到數字和觀測時間直接變新，落後標記消失，不必另外重新整理。
7. 身為使用者，查完後我想讓入口冷卻一小段時間，避免我連按把請求打太多次。
8. 身為使用者，查詢失敗時我想在入口旁邊看到簡短的原因，並知道可以改在 Claude Code 執行 `/usage`。
9. 身為使用者，查詢失敗時我想讓原本的讀數照常顯示，不被清空、不變成錯誤畫面。
10. 身為使用者，失敗原因我想分得出是找不到 `claude` 指令、查詢逾時、Claude Code 回報錯誤，還是 Claude Code 沒有寫回額度快取，才知道要修哪裡。
11. 身為使用者，Claude Code 回報錯誤時，我想看到它的原始訊息（例如沒有登入），不要被翻譯成看不出原意的文字。
12. 身為使用者，我想在命令列執行一個 `query` 子指令查詢額度，看到成功與新的觀測時間，或失敗原因，並由結束代碼判斷成敗，才能在別的腳本裡呼叫。
13. 身為使用者，查詢時我想要不跳出任何主控台視窗、不搶走焦點。

### 使用者：自動查詢

14. 身為使用者，我想自己決定要不要讓工具自動查詢；沒開啟時，工具不會主動請 Claude Code 發任何請求。
15. 身為使用者，我想在右鍵選單一鍵開關自動查詢，重新啟動後仍然保留。
16. 身為使用者，開啟後我想讓工具只在使用中帳號的讀數落後或讀數待更新時才查詢，平常閒置時完全不查。
17. 身為使用者，我想設定兩次查詢之間至少隔多久（預設 15 分鐘），手動查詢、自動查詢，以及我自己在 Claude Code 打的 `/usage` 都算一次。
18. 身為使用者，我把間隔設得比下限（5 分鐘）還小時，我想讓工具以下限執行並提示我，而不是照我設的值連打。
19. 身為使用者，我想讓工具不改寫我在設定檔裡填的值，即使它低於下限。
20. 身為使用者，人離開電腦時，我想讓自動查詢在最後一次對話之後最多再查一次就停下來。
21. 身為使用者，我離開時如果還有長任務、背景子代理或排程在跑，我想讓工具照間隔繼續查詢，因為額度真的在消耗。
22. 身為使用者，自動查詢連續失敗 3 次時，我想讓它暫停，並在卡片上看到「自動查詢已暫停」與最後一次失敗的原因，避免在被限流時越打越久。
23. 身為使用者，暫停之後我想用一次成功的手動查詢讓自動查詢恢復，不必重新啟動工具。
24. 身為使用者，單次失敗時我想讓工具等滿一個間隔才再試，不要立刻重試。
25. 身為使用者，多個 Claude Code session 同時在跑時，我想讓工具只查一次使用中帳號，不因為 session 多就多查。

### 使用者：切換帳號

26. 身為使用者，我在工具外切換帳號時，想讓舊帳號那份已經落後的讀數在待命卡片上標成「切換前已落後」，不要看起來像準確的讀數。
27. 身為使用者，我想讓「切換前已落後」一直保留到該帳號再次出現新讀數為止，重新啟動工具後也一樣。
28. 身為使用者，切換前最後一分鐘才有的對話活動，我也想讓它算進「切換前已落後」的判斷，不因為落後判定一分鐘才掃一次而漏掉。
29. 身為使用者，切換後新帳號處於讀數待更新、而且自動查詢已開啟時，我想讓工具依同樣的間隔規則替新帳號查詢。
30. 身為使用者，查詢進行到一半時剛好切換帳號，我想讓查回來的讀數依額度快取裡的帳號識別碼歸屬，不會算到錯的帳號上。

### 使用者：設定與部署

31. 身為使用者，`claude` 指令不在開機自動啟動看得到的 PATH 時，我想在設定檔填入它的完整路徑。
32. 身為使用者，我在設定檔填了 `claude` 的路徑、但那個檔案不存在時，我想讓查詢失敗並告訴我，而不是退回去找 PATH 裡的另一個 `claude`。
33. 身為使用者，我改了 `claude` 路徑或自動查詢的設定後，想要不必重新啟動就生效。
34. 身為使用者，我把 Claude Code 目錄搬到別處（設定檔欄位或 `CLAUDE_CONFIG_DIR`）時，我想讓查詢更新的正是工具在讀的那份額度快取。
35. 身為使用者，我想讓查詢不觸發我在 Claude Code 設定的任何 hooks（音效、備份、提醒）。
36. 身為使用者，我想讓查詢不修改 Claude Code 的任何設定檔，也不產生新的對話紀錄。
37. 身為架設者，我想在 README 讀到：工具預設不發任何請求；只有按下按鈕或開啟自動查詢時，才會請 Claude Code 代查；以及代查的成本與風險（打的是與 `/usage` 相同的端點，太頻繁可能被限流，限流期間連自己打的 `/usage` 也會失敗）。
38. 身為架設者，我想在 README 讀到三個新設定欄位的意義、預設值與下限。
39. 身為架設者，我想在 README 讀到本工具是依哪一種使用情境設計與測試的，以及已知的限制，才能判斷它適不適合我的用法。
40. 身為使用者，我想在兩個語系下看到所有新文字，而且卡片上的新文字不會跟既有文字重疊。

### 維護者

41. 身為維護者，我想讓額度快取仍然是用量讀數的唯一來源，查詢只負責「讓它變新」，不新增第二條資料路徑。
42. 身為維護者，我想讓查詢是否成功只依額度快取的觀測時間有沒有前進來判斷，不依賴 Claude Code 標為實驗性的回應格式。
43. 身為維護者，我想讓 Claude Code 的查詢介面改版時，失敗被歸類並顯示出來，工具的其他功能照常運作。
44. 身為維護者，我想用一支假的 `claude` 執行檔測試整個查詢流程（成功、逾時、回報錯誤、沒有寫回），不必真的呼叫 Claude Code。

## 實作決策（Implementation Decisions）

- **查詢的做法**（ADR-0010）：開一個 Claude Code 子行程，以 print 模式加上 stream-json 輸入輸出，先送 `initialize` 控制請求，再送 `get_usage` 控制請求，收到 `get_usage` 的控制回應後關閉輸入。子行程一律帶 `--settings '{"disableAllHooks":true}'`。查詢不送任何使用者訊息，所以不跑模型。實測一次約 4 秒、會寫回額度快取、不產生對話紀錄。
- **與核心的關係**：查詢是非同步的。GUI 每輪 poll 都只檢查子行程狀態，不等它結束；視窗不能因為查詢而凍結。核心負責決定要不要自動查詢、記錄查詢狀態，並把狀態放進看板；畫面層只負責呈現與觸發。
- **成功的判定**：記下查詢開始前額度快取的觀測時間，在逾時之前，看到觀測時間比它新就算成功。子行程正常結束、但觀測時間沒有前進時，算失敗（「Claude Code 沒有寫回額度快取」）。查詢的回應內容不解析。
- **固定值**（不屬於設定）：逾時 20 秒，逾時就結束子行程；手動查詢完成後冷卻 30 秒；自動查詢間隔下限 5 分鐘；自動查詢連續失敗 3 次就暫停。逾時以核心的時鐘計算。
- **失敗原因**分四類：找不到 `claude` 執行檔（含設定的路徑不存在）、逾時、Claude Code 回報錯誤（附它的原始訊息，不翻譯）、Claude Code 沒有寫回額度快取。
- **自動查詢的觸發條件**（全部成立才查）：自動查詢已開啟；使用中帳號的卡片是落後讀數或讀數待更新；目前沒有查詢在進行中；自動查詢沒有暫停；距離「工具上一次查詢的開始時間」與「目前讀數的觀測時間」兩者中較晚的那個，已經滿一個間隔。後者讓使用者自己打的 `/usage` 也算一次查詢。
- **暫停與恢復**：自動查詢連續失敗 3 次就暫停；任何一次查詢成功（手動或自動）都會把連續失敗次數歸零，並解除暫停。單次失敗後照常等滿一個間隔。查詢狀態（進行中、冷卻、最後一次失敗、連續失敗次數、暫停）只存在記憶體，重新啟動後從頭開始。
- **新設定欄位**（放在 `providers.claude` 底下，與既有的供應商設定並列，執行中改了下一輪就生效）：
  - `claudeCommand`：`claude` 執行檔的完整路徑，`null` 表示從 PATH 找。有填、但檔案不存在時，查詢失敗，不退回 PATH（與 ADR-0008 的路徑規則同精神）。
  - `autoUsageQuery`：`true`／`false`，預設 `false`。
  - `autoUsageQueryMinutes`：正整數，預設 15。低於 5 時以 5 執行，看板帶出「低於下限，以 5 分鐘執行」的提示，不改寫設定檔；不是正整數時當成不合法，改用預設，照既有的不合法設定流程提示。
  - 右鍵選單提供自動查詢的開關，寫回 `autoUsageQuery`。間隔與 `claude` 路徑只能在設定檔調整。
- **子行程的環境**：Claude Code 目錄的來源是 home 預設時，從子行程的環境變數移除 `CLAUDE_CONFIG_DIR`；來源是設定檔欄位或環境變數時，把 `CLAUDE_CONFIG_DIR` 設成工具解析出的目錄。這樣查詢寫回的一定是工具在讀的那份額度快取。工作目錄用不屬於任何專案的暫存目錄；Windows 上不開主控台視窗。
- **看板的變更**：
  - 看板新增查詢狀態：進行中、冷卻中、最後一次失敗的原因、自動查詢是否開啟、是否已暫停、間隔是否低於下限。
  - 卡片的落後讀數不再只屬於使用中帳號：待命帳號的讀數也可能是落後（切換前已落後）。畫面層依卡片的角色決定文字。
- **切換前已落後**：
  - 偵測到切換的那一輪，不管距離上次掃描多久，都對舊帳號的讀數重新判斷一次落後，並把結果和那份待命讀數一起存進工具狀態。
  - 待命卡片顯示存著的落後狀態；該帳號的讀數換成新的（觀測時間不同）時清除。
  - 存放格式要能讀懂沒有這個狀態的舊檔，當成沒有落後。
- **入口**：
  - 使用中帳號的卡片在落後讀數或讀數待更新時，在提示旁邊加一個可點擊的「更新」入口，三種版面都有。進行中或冷卻中時顯示為不可點，失敗原因與「自動查詢已暫停」顯示在同一處。
  - 右鍵選單有「查詢額度」，任何時候都可以用（進行中或冷卻中時不可點）。
  - 命令列新增 `query` 子指令：同步執行一次查詢並等它結束。成功時印出新的觀測時間，結束代碼 0；失敗時印出原因與 `/usage` 退路，結束代碼 1。命令列不受 GUI 的冷卻限制（不同程序，不共享狀態）。命令列 `list` 在落後或讀數待更新時，寫出一句完整說明：可以執行 `query`，或在 Claude Code 執行 `/usage`。
- **README**（英文與正體中文版同一次編輯）：開頭的承諾改成「預設不發任何請求、不修改 Claude Code 設定；只有你按下按鈕或開啟自動查詢時，才會請 Claude Code 代查」；新增一段說明查詢額度的作用、成本與限流風險；設定欄位表加三個新欄位；〈目前版本的範圍外〉的「任何網路請求」改成與新承諾一致的說法。
- **README 新增〈適用情境與已知限制〉**（兩個語言版本）：寫明本工具是依一種特定使用情境設計與測試的——Windows、Claude Code（訂閱方案）、對話主要在 VS Code 的 Claude Code 面板中進行、同一台電腦輪流使用多個帳號；其他情境（只用終端機、多台電腦、多人共用）沒有測試過，日後要擴充通用性時再改寫這一段。已知限制至少列出：只能查詢與即時判斷使用中帳號、在別的裝置或 claude.ai 網頁用掉的額度看不出落後、卡片上的「更新」只在落後或讀數待更新時出現（其他時候用右鍵選單）、依賴 Claude Code 未公開的欄位與實驗性介面。
- **用詞**：文件、程式碼、文案一律用「查詢額度（Usage Query）」，不用「刷新」（那是憑證刷新）。按鈕上的文字可以叫「更新」。

## 測試決策（Testing Decisions）

- **好的測試只看外部行為**，沿用既有的縫，不新增縫：
  - **縫 ①**：核心的 poll 與查詢入口回傳的看板，以及它寫進工具狀態的檔案。查詢的子行程**不另開縫**：測試在假 home 的設定檔裡，把 `claudeCommand` 指向一支假的 `claude`（小型 Python 腳本），由它扮演 Claude Code：讀取控制請求、依測試指定的劇本改寫假的額度快取、回應或不回應、以指定的結束代碼結束。逾時以 FakeClock 推進，測試不實際等 20 秒。
  - **縫 ②**：畫面層渲染後的 Canvas item。三種版面、兩個語系下，新增的入口、狀態與失敗原因跟既有文字的外框不重疊，提示維持單行；入口在進行中或冷卻中時不可點。
  - **縫 ③**：三個新設定欄位的預設值、不合法值、低於下限，以及設定檔寫出的預設內容。
  - 命令列 `query` 與 `list` 用既有的命令列測試寫法（呼叫 main、比對輸出與結束代碼）。
- 縫 ① 至少涵蓋：
  - 手動查詢成功後，觀測時間前進、落後清除；冷卻期間不能再查，冷卻結束後可以
  - 四種失敗原因各一；失敗時讀數不變
  - 設定的路徑不存在時失敗，不退回 PATH
  - 自動查詢：預設關閉時從不查；開啟後只在落後或讀數待更新時查；閒置（沒有新對話紀錄）時不查；間隔以「上次查詢」與「讀數觀測時間」中較晚者起算；低於下限時以下限執行並帶出提示
  - 連續 3 次失敗後暫停、手動成功後恢復；單次失敗後等滿一個間隔
  - 查詢不產生對話紀錄，所以不會自己觸發下一次自動查詢（以假 `claude` 不寫對話紀錄、並斷言查詢後不落後來驗證）
  - 子行程收到的 `CLAUDE_CONFIG_DIR` 與 hooks 關閉參數（假 `claude` 把收到的參數與環境寫出來給測試斷言）
  - 切換前已落後：切換前落後的讀數，切換後在待命卡片上仍是落後；切換前一分鐘內的對話也算；重新啟動後保留；新讀數出現後清除；舊格式的工具狀態檔讀得懂
  - 查詢進行中發生切換，讀數依額度快取的帳號識別碼歸屬
- **手動驗證**（實測，寫進票的驗收清單）：
  - 真實的 Claude Code 上，按一次按鈕，額度快取被寫回、卡片數字變新
  - VS Code 面板開著、閒置一小時，自動查詢沒有因為閒置的 session 寫對話紀錄而被觸發。這是現有落後判定的未驗證前提；不成立的話停下來回報，不自行改判定規則
  - 開機自動啟動的工具也找得到 `claude`（或依 README 填了路徑後找得到）
- **先例**：落後讀數的測試（假 home 加上對話紀錄、FakeClock）、設定的不合法值與預設值測試、命令列輸出測試、版面的 Canvas item 外框不重疊測試。
- 測試框架維持標準庫的 `unittest`。

## 範圍外（Out of Scope）

- **statusLine 資料源**：面板模式不執行 statusLine（`.scratch/statusline-usage-source/issues/01-statusline-rate-limits-source.md`，wontfix）。
- **查詢待命帳號**：例如用憑證快照的副本讓 Claude Code 代查。已否決：Claude Code 可能在副本裡刷新 token，造成憑證快照失效；憑證快照也會被複製到納管目錄以外。從工具內切換時，可以在切換前先查一次，所以沒有必要。
- **從工具內切換時，先查詢再切換**：歸屬「從工具內切換帳號」那個 feature，到時候再 grill。
- **固定間隔的定時查詢**、讀數沒有落後時的自動查詢：等於定時輪詢供應商的端點（ADR-0010）。
- **查詢間隔加隨機秒數**：限流看的是頻率，隨機秒數不會降低頻率；讓請求看起來不像程式發的，屬於偽裝。
- **解析 `get_usage` 的回應**、把回應當成第二個資料來源。
- 在別的裝置或 claude.ai 網頁用掉的額度：本機沒有對話紀錄，落後判定看不出來，自動查詢也不會觸發。這是既有的限制。
- 命令列與 GUI 之間共享冷卻或暫停狀態。
- 落後讀數判定規則本身的修改。

## 補充說明（Further Notes）

- 取代 `.scratch/usage-refresh-hint/issues/01-usage-refresh-hint.md`（wontfix）。該票的 `list` 說明與 README 段落由本 spec 吸收；失敗訊息的「可改在 Claude Code 執行 `/usage`」涵蓋它原本的用途。
- 依賴：「切換前已落後」要把狀態存進納管目錄的工具狀態。`.scratch/managed-directory/` 正在把納管目錄的讀寫集中到一個 module。碰到工具狀態的票，排在那個 feature 的票之後；不碰工具狀態的部分（查詢本身、設定、入口）可以先做。
- `get_usage` 在 Claude Code 裡被標為實驗性（Claude Code 2.1.285／擴充套件 2.1.286 時實測）。它改版時，查詢會歸類成「Claude Code 回報錯誤」或「沒有寫回額度快取」，不影響其他功能。
- 卡片與命令列的新文案，在實作前與使用者確認。
- 查詢狀態（連續失敗次數、暫停）目前只存在記憶體。納管目錄 module 完成後，再評估要不要持久化（重新啟動後仍維持暫停）。
- 間隔下限 5 分鐘是推測值，供應商沒有公開這個端點的限流門檻。
