## Comments

- 實作：入口從版面 A 抽成三版面共用的 `entry.py`（`UpdateEntry`：一個 Canvas 文字 item，管位置、字型、顏色、點擊、游標；標籤與可不可點仍由 `canvas_text.query_entry` 決定，兩種標籤的語系鍵放在 `canvas_text.ENTRY_LABELS`）。版面 A 改用它，行為不變。`widget.py` 對三種版面都傳 `on_query`。`card_notes` 加 `expiry_info`（版面 B 的表格另有欄位顯示憑證到期）。
- 實作前與使用者確認的位置（spec 沒寫）：展開模式照版面 A，入口與落後（或讀數待更新）那條提示同一行靠右、狀態接在底下。版面 B 的單行條與版面 C 的精簡模式把提示收成「● N 則提示」，入口放在那一行的右側，查詢中／失敗原因／自動查詢已暫停另起一行放在下方、全文顯示、不計入提示數量。沒有入口時（右鍵選單查詢）狀態行照樣顯示。
- 版面 B 的單行條有狀態行時，卡片至少與版面 A 的卡片同寬（扣掉內距），失敗原因才不會折成很多行；入口靠右對齊橫條右緣。版面 C 展開模式並列多格時，狀態行與其他提示一樣冠上帳號標籤。
- 待命帳號沒有入口也沒有狀態行（`query_entry`／`query_notes` 已保證）。落後的 `NO_READING` 帳號，以及與其他帳號並列的未納管帳號，英文提示在版面 C 可能折成兩行；實際上落後要有讀數才成立，走不到，未加測試。
