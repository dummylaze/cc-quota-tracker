# 05: 自動查詢：設定、觸發條件、暫停與恢復

**What to build:** 使用者可以選擇開啟自動查詢（預設關閉）。開啟後，只在使用中帳號的讀數落後或讀數待更新時才查詢，兩次查詢之間至少隔設定的間隔（`autoUsageQueryMinutes`，預設 15，下限 5；低於下限時以 5 執行並在看板帶出提示，不改寫設定檔；非正整數時當不合法、改用預設並走既有的不合法設定提示）。間隔自「工具上一次查詢的開始時間」與「目前讀數的觀測時間」中較晚者起算，所以使用者自己打的 `/usage` 也算一次。連續失敗 3 次暫停，卡片顯示「自動查詢已暫停」與最後失敗原因；任何一次成功的查詢（含手動）解除暫停並歸零；單次失敗等滿一個間隔再試。右鍵選單可一鍵開關，寫回 `autoUsageQuery` 並在重新啟動後保留。閒置時讀數不落後，自動查詢自然停止。新文案實作前先與使用者確認。

## Comments

- 手動驗證（VS Code 面板開著、閒置一小時）尚未做，需要實機觀察；其餘驗收條件皆已驗證。不成立時停下來回報，不自行改落後判定規則。
- 實作時的詮釋：① 連續失敗次數計入手動與自動的所有查詢，任一次成功（含手動）歸零；② 30 秒冷卻只在手動查詢完成後起算，自動查詢有自己的間隔；③ 間隔低於下限的橫幅提示只在自動查詢開啟時出現；④ 命令列的核心不做自動查詢（`Core(auto_query=False)`），因為命令列 poll 一次就結束，不該留下查詢。

- 2026-10-02 修正上一則的 ①：連續失敗次數只數自動查詢的失敗；手動查詢失敗既不累計也不歸零，任一次成功（手動或自動）才歸零並解除暫停。30 秒冷卻仍只管手動查詢。
