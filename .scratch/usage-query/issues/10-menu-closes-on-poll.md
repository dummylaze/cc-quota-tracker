# 10: 右鍵選單開著時，每輪 poll 讓選單閃掉或關閉

**What to build:** 修正缺陷：右鍵選單開著時，視窗每 5 秒 poll 一次。這時游標停在主選單項目上，反白會消失（看起來閃一下）；如果展開的是「語系」「主題」「透明度」的子選單，整個選單會被關掉。修正後選單要能一直開著，直到使用者自己關掉；查詢額度的可點／不可點仍然跟著查詢狀態走。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 原因定位到單一動作，修正後同一個重現不再關閉選單
- [x] 回歸測試：查詢狀態沒變的幾輪 poll 不改動選單項；狀態真的改變時才改一次

## Comments

- 來源：使用者實機使用時回報。引入於 `04-manual-query-entry-layout-a.md`（選單項「查詢額度」隨查詢狀態 enable／disable）。04 已 `resolved`，依規則不重開，在此開新票；兩邊以路徑互指，不寫進 `Blocked by`。
- 原因：`Widget._sync_query_menu` 每輪 poll 都對主選單的「查詢額度」呼叫 `entryconfigure(state=...)`，即使值沒變。Windows 上，改動彈出中的選單項會重建原生選單：主選單的反白被清掉；第 2 項以後的子選單被收掉，整個選單跟著關閉。第 0 項「版面」不受影響，原因沒有追查。對子選單的 radiobutton／checkbutton 變數做 `set()`、改「自動查詢額度」的勾選，都不會關閉選單（逐一實測過）。
- 修正：狀態沒變就不呼叫 `entryconfigure`。剩下的情況是查詢開始或結束的那一輪：如果使用者剛好展開著子選單，選單仍會關一次，這種情況很少見，接受。
- 重現方式（Windows）：選單視窗的 class 是 `#32768`。另開執行緒用 `EnumWindows` 依 PID 數可見的選單視窗，選單打開後用鍵盤注入展開指定的子選單，在選單開著時呼叫一次 `refresh()`，看選單視窗數是否提早歸零。修正前展開「語系」「透明度」時 6 輪有 5 輪關閉、「版面」3 輪都不關；修正後 16 輪都不關。這個迴圈需要真實桌面與鍵盤注入，沒有放進 repo。
- 測試的縫只到「選單項有沒有被改動」（`tests/test_widget_query.py`），碰不到原生選單真的被關閉這一層，所以實機行為留給上面的手動驗證。
- 2026-10-03：第一次修正後手動驗證，子選單不再關閉，但游標停在「查詢額度」時反白仍每 5 秒閃掉。原因：游標停在某一項時，Tk 把它的 state 設成 `active`；修正拿目前的 state 跟 `normal` 比，`active` 被當成狀態改變，於是照樣每輪 `entryconfigure`。只有被懸停的那一項會出事，所以只剩「查詢額度」還閃。改成只比較可不可點（`disabled` 與否）。第一次修正時「閃一下」只是推定與子選單同因，沒有為它單獨建重現；這次補上：反白停在「查詢額度」時跑一輪 poll，修正前每輪呼叫 1 次 `entryconfigure`，修正後 0 次。回歸測試加一則：項目被 activate 時 poll 不改動它。
- 2026-10-03：手動驗證通過（第二次修正後重新啟動視窗）：游標停在「查詢額度」「自動查詢額度」超過 10 秒反白不閃；展開「語系」「主題」「透明度」子選單各 10 秒以上不關閉；「版面」子選單與「置頂」「開機自動啟動」行為不變。結案。
