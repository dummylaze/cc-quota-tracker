# 04: 版面 A 的「更新」入口與右鍵「查詢額度」

**What to build:** 在版面 A，使用中帳號的卡片在讀數落後或讀數待更新時，提示旁邊出現可點的「更新」入口；按下後進入「查詢中」並不可再按，成功時數字與觀測時間直接變新、落後標記消失，失敗時在同一處顯示簡短原因與 `/usage` 退路，冷卻中顯示為不可點。右鍵選單新增「查詢額度」，任何時候都可用（進行中或冷卻中不可點）。所有新文案在兩個語系都有，且卡片上的新文字不與既有文字重疊、提示維持單行。新文案實作前先與使用者確認。

## Comments

- 實作：`canvas_text.query_entry`／`card_notes`（入口與提示、失敗原因的文案與排序）、`layout_a._CardView._notes`／`_place_entry`、`Widget.query_usage`、選單項「查詢額度」（隨看板的查詢狀態 enable／disable）。核心沒動。版面 B、C 不接線，留給 06：`widget.py` 目前只對版面 A 傳 `on_query`，06 補上時一起改。
- 實作前與使用者確認的文案：入口「更新／Update」（純文字加底線，不填色）；進行中「查詢中…／Updating…」；冷卻中標籤不變、灰字不可點；右鍵選單「查詢額度／Query usage」；有入口時待更新提示改短句「讀數待更新／Reading pending」（原句在 300px 卡片上會折行，放不下入口又維持單行；原句仍留給命令列與版面 B、C）；失敗提示「查詢失敗：{原因}。在 Claude Code 執行 /usage」（中文不帶「可改」，英文 `Update failed: {reason}. Try /usage in Claude Code instead`），Claude Code 的原始訊息超過 60 字截斷加「…」、換行收成空白。
- 沒有入口時的呈現：失敗原因在任何狀態都顯示、直到下一次查詢成功，所以不落後時從右鍵選單查詢失敗也看得到；查詢進行中但沒有入口時（右鍵選單觸發）多一行「查詢中…」提示，進度才有地方看。冷卻中且沒有入口時不顯示任何東西。未納管卡片與使用中帳號卡片同樣處理（`role` 不是待命就算），只是目前它不會落後也不會讀數待更新，實際上不會出現入口。
- 失敗原因那一行可以折成多行（只保證不與既有文字重疊、不超出卡片內距）；「提示維持單行」指入口旁的落後與待更新提示。
- 查詢進行中 poll 間隔改為 500ms（`QUERY_POLL_MS`，平時仍 5 秒），查完的新讀數才不必再等一整輪；冷卻結束後入口與選單項恢復可點，最多還要等下一輪 poll（5 秒）。spec 沒寫這兩點，是實作時補的。
- 游標移到可點的入口變手形；入口在懸停期間變成不可點或被藏起來時，手形由版面自己收掉（`<Leave>` 在這種情況不會觸發）。
- 新增設計 token：字型角色 `link`（同 `small`，加底線）、間距 `entry_gap`。
- 測試：`tests/test_layout_a_query.py`（縫 ②：入口、狀態、失敗原因、不重疊、單行、不可點，兩個語系）、`tests/test_widget_query.py`（選單項與入口接線、進行中 poll 間隔）。Canvas 要視窗真的顯示才會依游標挑出被點的 item，點擊測試把視窗搬到螢幕外再顯示。既有版面測試一行未改；`tests/test_widget.py` 只改了兩個選單項目清單的期望值。
- 手動驗證：真實 Claude Code 上點一次入口，約 3 秒完成，卡片的讀數年齡由 46 分鐘變 0、落後提示與入口消失、選單項目進入冷卻（不可點）。
- 2026-10-03：事後發現缺陷：選單項「查詢額度」每輪 poll 都被 `entryconfigure`，Windows 上會讓開著的右鍵選單閃掉，展開某些子選單時整個選單關閉。修正與驗收見 `10-menu-closes-on-poll.md`。
