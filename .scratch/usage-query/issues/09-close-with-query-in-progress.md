# 09: 視窗關閉時還在進行中的查詢

**What to build:** 先釐清、再決定：使用者在查詢進行中關閉視窗（選單「結束」），Claude Code 子行程會怎麼樣、需不需要由本工具主動結束它。若需要，核心提供結束進行中查詢的入口，視窗關閉時呼叫；若評估後不需要，結論寫進本票 Comments 並以 `wontfix` 結案，不改程式。

**Blocked by:** None (can start immediately)

**Status:** needs-triage

## 已知與未知

| 前提 | 出處 | 內容 |
|---|---|---|
| 視窗關閉時，`Widget.close` 不處理進行中的查詢 | 實測（讀碼） | `widget.py` 的 `close` 只取消計時、存位置、銷毀版面與視窗；核心的 `Core._query` 與子行程無人收尾 |
| 子行程在輸入關閉後會自己結束 | 推測 | `usage_query.py` 的 `check` 與 `01`、`03` 的設計都假設「關閉輸入、Claude Code 自己結束」；在**視窗行程結束的那一刻**（管道被作業系統關閉）沒有實測過 |
| 子行程卡住時（超過 20 秒逾時）會殘留 | 推測 | 逾時由 `check` 強制結束，但那要靠 poll 繼續跑；視窗已關閉就沒有人呼叫 `check` |
| 命令列 `query` 被 Ctrl+C 中斷時的情形 | 未知 | 同步查詢 `Core.query_usage` 迴圈中被中斷，子行程是否殘留未查 |

## 要先做的事

- [ ] 實測：查詢進行中關閉視窗，子行程是否在數秒內自行結束（Windows；有 `taskkill` 與批次檔包裝的 npm 版本也看一次）。結果寫進 Comments，並標明是實測
- [ ] 實測：命令列 `query` 進行中按 Ctrl+C，子行程是否殘留
- [ ] 依實測結果與使用者確認：要不要做、做到哪（只處理視窗、或連命令列）

## 若決定要做（暫定，確認後再收斂）

- [ ] 縫 ① 測試：核心提供結束進行中查詢的入口，呼叫後子行程已結束、看板的查詢狀態不是進行中，也不記成失敗、不啟動冷卻
- [ ] 沒有進行中的查詢時呼叫該入口什麼都不做
- [ ] 視窗關閉時呼叫該入口（視窗測試）
- [ ] 既有縫 ① 與視窗測試一行未改、全部通過
