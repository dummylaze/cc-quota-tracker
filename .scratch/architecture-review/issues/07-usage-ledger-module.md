# 07: 用量帳本收成一個 module（檔案、鎖、狀態、帳號標籤對照）

> *This was generated by AI during an architecture review.*

**What to build:** 用量帳本這一個概念，現在由三個 module 各握一段：

- `cc_quota_tracker/usage_ledger.py`：檔案格式（`encode_batch`、`decode`）與跨行程的鎖（`exclusive`）
- `cc_quota_tracker/managed_directory.py`：檔案路徑、`read_usage_ledger`、`update_usage_ledger`、`_ledger_ends_mid_line`、權限收緊、`read_ledger_status`／`write_ledger_status`、`read_account_labels`／`write_account_labels`
- `cc_quota_tracker/token_report.py`：`update_ledger` 的狀態轉換（成功、失敗、被別的行程擋住而跳過、狀態檔寫不成），`update_labels` 對帳號標籤對照的讀改寫

要搞懂「帳本更新失敗時會發生什麼」，得在三個檔案之間來回。另外帳號標籤對照的讀改寫不在帳本的鎖裡，正是 `token-report-backlog/01` 記下的缺口（兩個 `report` 同時跑時，未監看帳號的編號會撞號）。

方向：帳本、它的狀態檔與帳號標籤對照由一個 module 持有，對外大致是：讀回、依計畫追加並回傳更新後的狀態、在同一把鎖內更新對照。納管目錄只提供 `.state/` 的位置與權限收緊。

開工前要先決定：
- 權限收緊（`_tighten`）留在納管目錄、以參數交給這個 module，還是由它自己做（`permissions` 已經是獨立 module）
- 要不要順帶處理 `token-report-backlog/01` 的鎖缺口；那張票還沒分流，兩張要一起看
