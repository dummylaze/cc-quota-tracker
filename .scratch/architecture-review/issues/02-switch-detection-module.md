# 02: 把切換偵測從 Core 拆成獨立的 module

> *This was generated by AI during an architecture review.*

**What to build:** `cc_quota_tracker/core.py` 的 `_observe`（67 行）連同 `_stale_snapshot`、`_mark_lagging_before_switch`，把切換偵測的判斷和檔案 I/O 混在一起：讀當前憑證、讀上一輪觀測、五個分支的切換判斷、失效旗標的兩段（暫定→持久）、標落後、追加切換紀錄、寫回觀測，全在同一個方法裡。Core 近期的修正多半落在這段（重新登入誤判、兩段失效旗標、寫回後憑證指紋改變），但 `tests/test_switch_detection.py` 的 40 個案例只能透過 `Core.poll` 加假 home 目錄測，每條規則都要登入、納管、poll、改檔、再 poll。

方向：判斷變成只吃值、回傳值的 module——輸入上一輪觀測、當前憑證（憑證指紋與到期時間）、帳號資訊的識別碼、監看帳號、這一輪的憑證同步結果；輸出當前憑證帳號、失效的憑證快照、切換事件（有沒有切換、切到哪個帳號識別碼、離開哪個帳號）與下一輪觀測。Core 只負責讀進來、依切換事件寫切換紀錄、標落後、寫觀測。

判斷規則的測試改成直接測這個 module；經過 Core 的測試留少量，驗證 I/O 串得起來。
