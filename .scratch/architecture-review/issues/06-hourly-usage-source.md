# 06: 用量帳本與最近的對話紀錄收成一個小時用量來源

> *This was generated by AI during an architecture review.*

**What to build:** token 報表的資料來源是「用量帳本的 through 之前的小時」加上「對話紀錄裡 through 之後的小時」，兩邊不重疊。這條不變式現在在 `cc_quota_tracker/token_report.py` 裡寫了兩次：

- `build_data`：`live = [u ... if ledger.through is None or _hour_of(u.at) >= ledger.through]`，再把帳本的格子加進同一份小時表
- `update_ledger` 內的 `plan`：`_hour_of(u.at) >= read.through and _hour_of(u.at) < through`，決定下一批入帳的格子

兩處各自建 `Attribution`、各自呼叫 `_hourly`（含 `_long_prompt` 依單價表拆長 prompt 的格子）。任何一處的比較改了而另一處沒跟上，用量會靜默重複計算或漏算，而且只有在 through 那一小時附近的測試抓得到。

方向：一個 module 吃對話紀錄的掃描結果、帳本讀回、切換紀錄、單價表，對外只給兩樣：報表用的小時格（帳本格 ∪ 最近的格），與下一批該入帳的小時格（到哪個小時為止）。through 的切線、歸屬、長 prompt 拆格都在它裡面。`build_data` 只把小時格換算成日與各種合計，不再碰對話紀錄；`update_ledger` 只負責寫入與狀態。

判斷規則的測試改成直接餵值測這個 module；`tests/test_usage_ledger.py` 現有走 `main(["report"])` 的案例保留，當回歸網。
