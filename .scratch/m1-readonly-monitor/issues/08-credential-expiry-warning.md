# 08: 憑證到期警示

**What to build:** 每張納管帳號卡片都帶著憑證快照還剩幾天到期；剩 7 天以內時發出警示，並附上完整補救步驟，讓使用者不會等到要用時才發現憑證已壞。

**Blocked by:** 05

**Status:** resolved

- [x] 到期時間取自憑證快照的 `refreshTokenExpiresAt`；看板帶到期時間，倒數由畫面層算（兩個單位＋絕對時間，一律捨去，格式依設定 `countdownFormat`）
- [x] 剩不到設定的天數（`providers.claude.expiryWarningDays`，預設 7 天；含已過期）→ 到期警示旗標；步驟為「在該帳號下重新登入，再對同一標籤重新執行 `add`」
- [x] 每張納管帳號卡片都帶到期時間，不論是否警示；沒有 `refreshTokenExpiresAt` 的快照暫當無效資料，不帶、不警示
- [x] 以縫 ① 的測試涵蓋：憑證快照 5 天後到期 → 發出警示

## Comments

- 2026-09-29：實作補充——剩餘天數不足一天算一天（無條件進位），警示以「剩餘時間 ≤ 7 天」判定，兩者用同一條界線：剩 7 天又 1 小時顯示 8 天、不警示。已過期的剩餘天數 ≤ 0，同樣警示，畫面顯示「已過期」。每輪以當下時間重算，檔案沒變也會跟著時間前進。未納管帳號沒有憑證快照、或快照沒寫 refreshToken 到期時間（`refreshTokenExpiresAt`）時，剩餘天數為空、不警示。
- 2026-09-29：實測發現一份沒有 `refreshTokenExpiresAt`、頂層多 `organizationUuid` 的憑證快照，暫當無效資料、不另外處理（記在 spec〈補充說明〉）。
- 2026-09-29：顯示方式改版（使用者決定）——取消無條件進位。看板改帶憑證快照的到期時間，不帶天數；倒數由畫面層算，工作階段窗口、週窗口、憑證快照三者共用：兩個單位（天＋時／時＋分）＋絕對時間，一律捨去。新增設定 `countdownFormat`（`twoUnits` 預設／`decimalDays` 天數到小數第 1 位，不到一天改顯示時＋分）。警示門檻由「≤ 7 天」改為「剩不到 7 天」，讓顯示「7天0小時」時一律不警示、「6天23小時」起才警示。驗收條件已依此改寫（原文為「剩餘天數」「≤ 7 天」）。
- 2026-09-29：警示天數改成設定（使用者決定）——設定檔新增按供應商分開的 `providers.claude`：`expiryWarningDays`（預設 7），連同百分比門檻 `warningPercent`／`criticalPercent`（預設 60／85，原為固定值）。預設值由供應商模組帶入；嚴重度推定從解析層移到核心每輪建卡片時，改設定下一輪生效。這些設定只放設定檔，不進右鍵選單（右鍵選單不能變長）。
