# 09: 綁定維護：直接放檔、改檔名、清理殘留

**What to build:** 讓使用者不透過 `add`，直接把憑證檔放進納管目錄或改檔名，也能被正確納管與維持身分綁定；刪檔後工具自己的殘留資料自動清掉。

**Blocked by:** 06

**Status:** resolved

- [x] 直接放進目錄、還沒有綁定的憑證快照，要同時符合三條件才補學綁定：它是使用中帳號、額度快取的識別碼與 `oauthAccount` 的識別碼一致、該識別碼尚未綁給其他帳號
- [x] 條件不符時不補學，該帳號維持「讀數待更新」，不猜測
- [x] 綁定以憑證指紋為鍵，改憑證快照檔名後綁定仍然保留
- [x] 憑證快照被刪除後，對應的孤兒綁定自動清除
- [x] 以縫 ① 的測試涵蓋：改檔名後綁定仍在、三條件缺一不補學

## Comments

- 2026-09-29：「身分鍵」改稱「憑證指紋」（CONTEXT.md）；內容不變。
- 補學與清孤兒都在每輪 poll 做（`add`／`remove` 之外的唯一寫綁定處）。綁定檔讀不到（例如被鎖住）、或有憑證快照讀不出憑證指紋時，這一輪不寫也不清，避免把暫時的讀取失敗當成刪檔。
- 票 06 的測試「使用中帳號沒有綁定仍是讀數待更新」前提剛好符合三條件，改成快取屬於別的帳號；補學的正面案例在 `tests/test_binding_maintenance.py`。
