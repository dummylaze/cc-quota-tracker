# 10: 落後讀數

**What to build:** 讓使用者分辨「讀數舊」與「讀數落後」：帳號閒置時舊讀數依然準確，不警示；只有讀數之後本機又有新的對話活動，才提示「有新對話，額度尚未更新」。

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] 使用中帳號的讀數觀測時間之後，本機的 Claude Code 對話紀錄有更新的修改 → 判為落後讀數
- [ ] 使用中帳號閒置、讀數再舊也不判為落後
- [ ] 待命帳號永遠不判為落後
- [ ] 掃描頻率可低於 poll，成本控制方式由實作決定；不得讓常駐記憶體持續上升
- [ ] 以縫 ① 的測試涵蓋：閒置舊讀數不落後、對話紀錄在讀數後更新 → 落後、待命帳號不落後
