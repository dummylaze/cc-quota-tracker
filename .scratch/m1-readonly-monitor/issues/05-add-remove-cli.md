# 05: 納管帳號：憑證儲存、add／remove 與命令列入口

**What to build:** 使用者在 Claude Code 登入某帳號後，用命令列執行 `add <標籤>` 就把該帳號納管，`remove <標籤>` 移除，`list` 看結果。`add` 當下就綁定該帳號的識別碼，並把存放憑證快照的目錄與檔案收緊到只有目前使用者能讀。這一票同時定義命令列的唯一入口，讓 README 與畫面上的提示都能引用完整寫法。

**Blocked by:** 02

**Status:** resolved

- [x] 憑證儲存介面提供讀取、身分鍵、內容雜湊三個方法，不回傳 token 本身；只實作檔案版本
- [x] 身分鍵是 refreshToken 雜湊的前 16 個十六進位字元；內容雜湊排除 accessToken 與到期時間，絕不對整份檔案雜湊
- [x] 帳號鍵格式為「供應商前綴:標籤」，標籤就是憑證快照的檔名去掉副檔名
- [x] 命令列有單一入口，以 `python -m <套件名> <子命令>` 執行，純標準庫；子命令為 add、remove、list；完整寫法記在 README 與未納管卡片可引用的一處
- [x] `add`：複製當前憑證成為憑證快照，綁定當下的 `oauthAccount` 識別碼；標籤已存在就覆寫（重新納管走這條）
- [x] `add` 主動收緊權限（Windows 移除繼承、只授權目前使用者），事後驗證，不符就修正並告警；在 Windows 真實暫存目錄上驗證
- [x] 標籤看起來像 email 時提示「這會顯示在畫面上」
- [x] `remove`：刪除憑證快照並清掉工具自己的綁定
- [x] 工具狀態寫入一律原子寫入：暫存檔建在目標同一目錄、帶明確前綴、權限錯誤重試 3 次每次 50 ms、失敗清掉殘留
- [x] 核心的 add／remove 是 GUI 也會呼叫的同一組操作，介面不依賴命令列
- [x] 本工具不讀取也不儲存 email；不寫入 Claude Code 維護的任何檔案

## Comments

- 看板暫時以 `Board.managed_accounts`（帳號鍵清單）帶出納管帳號，`list` 據此多印一行；卡片的角色與讀數歸屬是 06 的範圍，06 可以把這個欄位併進卡片。
- 憑證快照放在 `~/.claude-multi/<帳號標籤>.json`；工具狀態放在 `~/.claude-multi/.state/`（目前只有 `bindings.json`，以身分鍵為鍵）。點開頭的檔名不算憑證快照。
- `add` 讀不到 `oauthAccount.accountUuid`（例如 `~/.claude.json` 不存在）時仍寫入憑證快照，但不綁定並告警；之後的補學規則屬於 09。
- `add`／`remove` 寫綁定時，只保留仍有憑證快照對應的身分鍵；poll 時自動清孤兒綁定仍屬 09。
- 帳號標籤會直接成為檔名，所以另外擋掉路徑分隔、Windows 不接受的字元與裝置名稱、點開頭或結尾。
