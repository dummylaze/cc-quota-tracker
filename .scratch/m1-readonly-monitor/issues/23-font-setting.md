# 23: 字型設定，字型不存在時改用系統預設

**What to build:** 使用者可在設定檔指定介面字型；沒指定時用內建字型。不論內建或自填，字型在這台電腦上不存在時，一律改用系統預設字型，不讓 tk 自行替換成 Arial。

**Blocked by:** 14

**Status:** resolved

- [x] 設定檔新增 `font` 欄位，預設 `null`；第一次啟動寫出的完整設定檔包含它（spec〈路徑與設定檔〉）
- [x] 只能在設定檔調整，不進右鍵選單；依修改時間重讀，改了下一輪就生效
- [x] `null`：使用設計 token 的內建字型；填入字型家族名稱：所有文字改用它，字級與字重仍取自 token
- [x] 字型不存在（內建或自填）時改用 `TkDefaultFont` 的字型家族，不讓 tk 自行替換
- [x] 值不是字串也不是 `null`：照「單一欄位不合法」處理，那一欄用預設並在提示列出欄位名
- [x] 換字型只改既有 item 的字型屬性，不重建；縫 ②：來回切換字型，item 數不變
- [x] 實作前與使用者確認：自填的字型不存在時，要不要在看板提示（字型存不存在只有畫面層知道，與「要不要警示由核心決定」的判準要一起考慮）

## Comments

- 2026-09-29：開票依據：使用者問內建字型是否就是微軟正黑體，並提出「字型可設定」。實測 tk 找不到字型時會改用 Arial，不是系統預設字型。語系切到英文時是否要換字型，由票 16 決定。

- 2026-09-30：實作前與使用者確認：自填字型不存在時，在看板橫幅提示；內建字型不存在時不提示（那不是使用者填的）。縫 ② 的「item 數不變」詮釋為「同一個字型下來回切換不累積」：換字型會改變折行的行數（多行文字逐行一個 item），找不到自填字型時橫幅也多一段提示，所以不同字型之間的 item 數可以不同。自填空字串視為找不到的字型（橫幅顯示 `字型「」`）。
